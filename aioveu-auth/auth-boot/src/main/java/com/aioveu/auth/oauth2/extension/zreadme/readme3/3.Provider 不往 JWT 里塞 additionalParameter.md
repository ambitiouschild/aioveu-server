## 一句话答案

会写进 JWT（token）里。  
你这版代码里这两行：

```java
addClaim(claims, JwtClaimConstants.Token.USER_TYPE, "USER");     // 系统用户
addClaim(claims, JwtClaimConstants.Token.USER_TYPE, "MEMBER");   // 会员
```

✅ 只要 `addClaim` 没被拦截，就会成为 JWT 的 claim  
✅ 最终会在生成的 Access Token 的 Payload 里看到：

```json
{
  "user_type": "USER"
}
```
或
```json
{
  "user_type": "MEMBER"
}
```

## 为什么一定会写进去？（证据链）

### 1️⃣ `addClaim` 做了什么

```java
private void addClaim(JwtClaimsSet.Builder builder, String name, Object value) {
    if (value == null) return;
    if (value instanceof Collection<?> c && c.isEmpty()) return;
    builder.claim(name, value);
}
```

• `"USER"` / `"MEMBER"` ≠ null

• 不是空集合

✅ 必然执行 `builder.claim()`

---

### 2️⃣ `JwtClaimsSet.Builder` 就是 JWT 的草稿

```java
JwtClaimsSet.Builder claims = context.getClaims();
```

Spring Authorization Server 在最后：

```
JwtClaimsSet → JwtEncoder → 签名 → 最终 JWT
```

✅ 所有 `claim()` 都会进 token

---

### 3️⃣ 你的分支逻辑保证了一定会走到

```java
if (principal instanceof SysUserDetails) {
    addSysUserClaims(...) // 里面有 USER
    return;
}
if (principal instanceof MemberDetails) {
    addMemberClaims(...)  // 里面有 MEMBER
}
```

✅ 非此即彼，没有漏网之鱼

## 和你前面 Provider “不加进 token” 的矛盾吗？

不矛盾，是你两层都在写：

| 位置                                       | 写在哪里                               |
| ------------------------------------------ | -------------------------------------- |
| `CustomRefreshTokenAuthenticationProvider` | ✅ `Authorization.attribute(user_type)` |
| `JwtEncodingCustomizerConfiguration`       | ✅ JWT claim `user_type` ← 你现在问的   |

你之前说：

> “我不加进 token 了”

那是 指 Provider 不往 JWT 里塞 additionalParameters，  
但 Customizer 本来就是专职往 JWT 里写 claim 的，所以它写进去是完全正常且正确的。

## 一个微小但重要的提醒（定稿级）

你现在的常量名：

请确保它的值是：


否则 JWT 里会出现你没预期的名字。
