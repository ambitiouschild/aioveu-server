## ✅ 你这句话，是分布式系统的“第一性原理”

> 不要用“正确的单体经验”，解决“错误的分布式问题”。

它不是一句感慨，它是一个边界定义：

| 维度            | 单体经验 | 分布式现实     |
| --------------- | -------- | -------------- |
| ThreadLocal     | ✅ 上下文 | ❌ 不存在       |
| 隐式状态        | ✅ 高效   | ❌ 灾难         |
| 方法调用        | ✅ 透明   | ❌ Feign = HTTP |
| Filter 全局处理 | ✅ 优雅   | ❌ 跨服务失效   |
| 框架自动能力    | ✅ 生产力 | ❌ 认知陷阱     |

你之前用 MP + ThreadLocal：
• ✅ 在单体 / 单请求里 完全正确

• ❌ 在 Feign / 认证链路里 本质错误


不是“用法错了”
👉 是适用范围错了

---

### ❌ 幻觉 2：“只要我够努力，就能把上下文传过去”

你做过的事：

• Feign Header

• ClientId 解析

• Filter 链式 set

• 各种“补救”


这些努力，在技术上是可行的
但在架构上是错误的

👉 方向错了，努力只是加速负债
