## 一、先还原这行代码的逻辑真值表

```java
if (!(principalAttr instanceof UsernamePasswordAuthenticationToken authToken)) {
    log.warn("...");
    return;
}
```

### 假设几种情况：

| `principalAttr` 实际类型                | `instanceof` 结果 | `!` 取反 | if 是否成立 | 是否 return |
| --------------------------------------- | ----------------- | -------- | ----------- | ----------- |
| ✅ `UsernamePasswordAuthenticationToken` | true              | false    | ❌           | 不 return   |
| ❌ `String`                              | false             | true     | ✅           | return      |
| ❌ `OAuth2ClientAuthenticationToken`     | false             | true     | ✅           | return      |
| ❌ `null`                                | false             | true     | ✅           | return      |

✅ 你总结的那句是 100% 准确的：

> “如果不是，instanceof = false，取反为真，进入 if，return 空”

---

## 二、为什么是 `return`，不是“返回空”

这是非常关键的一个语义区别 👇

### 这段代码发生在哪里？

```java
public void customize(JwtEncodingContext context)
```

👉 返回类型是 `void`

所以这里的 `return` 意思是：

> “我不改 JWT claims，直接结束本次定制逻辑”

### 不是：

```java
return null;      // ❌ 根本不允许
return claims;    // ❌ 方法签名不支持
```

### 而是：

```java
context.getClaims(); // 不动
// JWT 正常生成
// 只是没有 tenantId / userId 等字段
```

---

## 三、从“JWT 视角”看这次 return 意味着什么

### ✅ 如果没进 if

```text
JWT claims:
- tenant_id = 3
- user_id = 10
- username = xinhuan
```

### ❌ 如果进了 if 并 return

```text
JWT claims:
- sub = clientId
- scope = ...
- （没有 tenant_id）
```

👉 JWT 仍然有效
👉 只是少了你自定义的 claim
👉 Spring Authorization Server 完全接受

---

## 四、为什么这里必须“空手而归”，而不能强行处理？

因为：

• 刷新令牌（`refresh_token`）不应该重新决定租户

• 客户端模式（`client_credentials`）本来就没有用户

• 历史授权记录可能结构不同


所以这里的 `return` 本质是：

> “我不知道你是谁，但我绝不乱填。”

这是 安全代码 的标准写法。

## 五、用一句“程序员黑话”总结你这句话

> “instanceof 为假，取反为真，直接 return，JWT 裸奔。”

或者更文雅一点：

> “类型不匹配，直接退出定制流程，不做任何租户声明。”
