## 一、先给你一个“一句话定义”

> `authorities` 是给 Spring Security 看的（认证）
>
> `perms` 是给前端 / 业务看的（状态）
>
> 两者都要“声明”，但地位完全不同

---

## 二、什么叫“perms 需要声明”？（你现在做的已经是对的）

### ✅ 1️⃣ 在 `SysUserDetails` 里“声明”它（✅ 必须）

```java
@Data
public class SysUserDetails implements UserDetails {

    /**
     * ✅ 认证主体（Spring Security 强制）
     */
    private Collection<? extends GrantedAuthority> authorities;

    /**
     * ✅ 用户态数据（业务需要，必须声明）
     */
    private Set<String> perms;
}
```

👉 这一步就叫“声明”
👉 不声明 = Jackson / Redis / JWT 都不知道它存在

---

### ✅ 2️⃣ 在 `@JsonCreator` 里“声明”它（✅ 必须）

```java
@JsonCreator
public SysUserDetails(
        @JsonProperty("authorities") Collection<? extends GrantedAuthority> authorities,
        @JsonProperty("perms") Set<String> perms
) {
    this.authorities = authorities;
    this.perms = perms;
}
```

👉 这是“序列化声明”
👉 没有这个，Redis / JWT 里都不会有 perms

---

### ✅ 3️⃣ 在 `JwtTokenCustomizer` 里“声明”它进 Token（✅ 推荐）

```java
claims.claim(JwtClaimConstants.User.PERMS, userDetails.getPerms());
```

👉 这是“JWT Claims 声明”
👉 不声明 = JWT 里没有

---

## 三、什么叫“perms 不需要声明成权限”？（非常关键）

### ❌ 错误示范（千万别这么干）

```java
// ❌ 把 perms 伪装成 authorities
.map(perm -> new SimpleGrantedAuthority(perm))
```

```java
@PreAuthorize("hasAuthority('user:add')") // ❌ 逻辑混乱
```

### ✅ 正确认知

| 概念          | 是否声明 | 声明给谁                          |
| ------------- | -------- | --------------------------------- |
| `authorities` | ✅        | Spring Security                   |
| `perms`       | ✅        | Jackson / Redis / JWT             |
| `perms`       | ❌        | `Authentication.getAuthorities()` |

## 四、你现在的逻辑，用一句话翻译过来是这样的

> 登录时：
> - 我从数据库拿到 `roles` → 声明成 `authorities`（给 Security）
> - 我从数据库拿到 `perms` → 声明成 `SysUserDetails.perms`（给用户态）

> Redis 里：
> - `SysUserDetails` 整体被序列化
> - `perms` 作为对象字段自然存在

> Refresh Token 时：
> - Redis → `SysUserDetails`
> - `perms` 自动回来

> JWT 里：
> - 我从 `SysUserDetails` 里读 `perms`
> - 声明进 JWT Claims

👉 全程没有“把 perms 当成权限”
👉 只是在“声明它是一个需要携带的数据”

👉 空姐才看“餐食偏好”（perms）
