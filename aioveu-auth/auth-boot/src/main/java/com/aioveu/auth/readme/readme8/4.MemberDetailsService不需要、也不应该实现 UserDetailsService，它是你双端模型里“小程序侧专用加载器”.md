## 一、先回答你这句话的“直球答案”

> 不需要实现 `UserDetailsService` 接口。

为什么？

你这个类：

```java
public class MemberDetailsService {
    // 没有 implements UserDetailsService
}
```

而你的方法：

```java
public MemberDetails loadMemberByOpenIdAndTenantId(String openId)
public MemberDetails loadMemberByOpenId(String openId)
public MemberDetails loadUserByMobile(String mobile)
```

✅ 都不是 `UserDetailsService#loadUserByUsername`
✅ 你也没在 `AuthenticationManager` / `DaoAuthenticationProvider` 里用它做“通用用户加载”
✅ 你是在 自定义 Provider（小程序 / 密码模式 / 刷新令牌）里手动调用的

👉 这是完全正确的设计，不是漏实现。

## 二、为什么“官方 `UserDetailsService` 你反而不该用”

Spring Security 的：

```java
public interface UserDetailsService {
    UserDetails loadUserByUsername(String username);
}
```

它的问题是：
| 限制                     | 你现在的业务                               |
| ------------------------ | ------------------------------------------ |
| 只能按 username          | 你要 openId、mobile、openId+tenantId       |
| 只能返回一个 UserDetails | 你要 MemberDetails / SysUserDetails 双模型 |
| 不知道租户               | 你有多租户                                 |

你现在的写法：

```java
MemberDetailsService  // 自己定义的业务服务
SysUserDetailsService // 自己定义的业务服务
```

✅ 比强行实现 `UserDetailsService` 更干净

## 三、但你这文件里，有 2 个真·会炸的 Bug（必须改）

### 🔴 Bug 1：注册时 `memberAuthDTO` 为 null 还 `.getTenantId()`

```java
if (memberAuthDTO==null) {
    ...
    memberRegisterInfo.setTenantId(memberAuthDTO.getTenantId()); // ❌ NPE
}
```

这里你还没注册，`memberAuthDTO` 是 null，却拿它取值。

✅ 正确写法（从 openId 查不到，但 tenantId 哪来？）

如果你前面 `authorization.getAttribute(JwtClaimConstants.Tenant.ID)` 有：
那这里应该由调用方传 tenantId，不是从 null 拿。

至少先防崩：

```java
if (memberAuthDTO == null) {
    MemberRegisterForm memberRegisterInfo = new MemberRegisterForm();

    // tenantId 必须从上下文/参数来，不能从 memberAuthDTO
    // memberRegisterInfo.setTenantId(???);
}
```

⚠️ 这是你前面 `CustomRefreshTokenAuthenticationProvider` 里 `authorization.getAttribute(tenantId)` 能传进来的地方。

```java
    memberAuthDTO = new MemberAuthDTO();
    BeanUtils.copyProperties(reg, memberAuthDTO);
}
```
