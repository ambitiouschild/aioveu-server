## ✅ 一句话先给结论

> `ClientIdGatewayFilter` 是「业务路由级过滤器」
>
> ✅ 只在需要 clientId / tenantId 的业务服务路由上挂
>
> ❌ 绝不挂在 `/oauth2/**`、`/auth/**`、公网接口
>
> 👉 它是“业务守门员”，不是“协议守门员”

---

## ✅ 一、它到底是干嘛的（先统一认知）

`ClientIdGatewayFilter` 负责三件事：

| 职责                    | 说明                   |
| ----------------------- | ---------------------- |
| ✅ 校验 `X-Client-Id`    | 是否是系统允许的客户端 |
| ✅ 解析 JWT → `tenantId` | 只解析，不校验         |
| ✅ 注入 `X-Tenant-ID`    | 给下游做“镜像租户”     |

它不干的事：

❌ 不校验 JWT 签名  
❌ 不校验过期  
❌ 不查黑名单  
❌ 不登录  

---

## ✅ 二、正确用法（推荐 ✅）

### ✅ 方式一：Gateway 路由 YAML 中挂载（最标准）

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: pms-service
          uri: lb://aioveu-tenant-pms
          predicates:
            - Path=/aioveu/api/v8/{segment}/pms/**
          filters:
            - StripPrefix=0
            - name: ClientIdGatewayFilter
              args:
                allowedClientIds: app,system
```

✅ 这是企业里最规范的做法
✅ Filter 只对这条路由生效
✅ 不污染其他路由

---

### ✅ 方式二：多个业务服务统一挂载（你现在的用法）

```yaml
# 商品服务
- id: pms
  uri: lb://aioveu-tenant-pms
  predicates:
    - Path=/aioveu/api/v8/{segment}/pms/**
  filters:
    - StripPrefix=0
    - name: ClientIdGatewayFilter

# 订单服务
- id: oms
  uri: lb://aioveu-tenant-oms
  predicates:
    - Path=/aioveu/api/v8/{segment}/oms/**
  filters:
    - StripPrefix=0
    - name: ClientIdGatewayFilter
```

✅ 非常适合中台
✅ 所有业务服务统一“安检”

## ✅ 三、哪些路由 **绝对不能挂**

### ❌ 1️⃣ 认证服务（Authorization Server）

```yaml
- id: auth
  uri: lb://aioveu-tenant-auth
  predicates:
    - Path=/aioveu/api/v8/{segment}/auth/**
  filters:
    - StripPrefix=0
    # ❌ 不要挂 ClientIdGatewayFilter
```

原因：
• auth 服务是 协议层

• clientId 由 `Authorization` Header / Basic 认证处理

• 网关不该插手


---

### ❌ 2️⃣ OAuth2 协议端点

```yaml
- Path=/oauth2/token
- Path=/oauth2/jwks
- Path=/oauth2/authorize
```

✅ 这些你已经单独拆路由了  
✅ 绝对不能再挂

---

### ❌ 3️⃣ 公开接口（不需要登录）

比如：
• 首页接口

• 商品浏览

• 公共配置


```yaml
# ❌ 不要挂
```

除非你明确希望：
> “即使是匿名请求，也要带 clientId”

## ✅ 四、前端 / 调用方该怎么配合

### ✅ 带 Token 的请求（登录后）

```http
GET /aioveu/api/v8/app/pms/spu/123
Authorization: Bearer eyJxxx...
X-Client-Id: app
```

网关会：
1. 解析 JWT → tenantId
2. 注入 `X-Tenant-ID`
3. 放行

---

### ✅ 不带 Token 的请求（匿名）

```http
GET /aioveu/api/v8/app/pms/spu/123
X-Client-Id: app
```

网关会：
1. 校验 clientId 白名单
2. 注入 `X-Client-Verified: true`
3. 放行

---

### ❌ 不带 clientId（直接拒绝）

```http
GET /aioveu/api/v8/app/pms/spu/123
```

👉 返回：
```json
{
  "code": 401,
  "msg": "缺失 X-Client-Id"
}
```

## ✅ 五、下游服务该怎么用（非常关键）

### ✅ 1️⃣ 优先信任 JWT（权威来源）

```java
Jwt jwt = ((JwtAuthenticationToken) authentication).getToken();
Long tenantId = jwt.getClaim("tenant_id");
```

---

### ✅ 2️⃣ 把网关 Header 当“校验镜像”

```java
String gatewayTenant = request.getHeader("X-Tenant-ID");
String gatewayClient = request.getHeader("X-Client-Id");
String verified = request.getHeader("X-Client-Verified");
```

✅ 可以用来：
• 审计

• 防篡改

• 日志

• 风控


❌ 不要当成唯一租户来源

## ✅ 六、常见坑（你现在已经避开了，但别人会踩）

| 坑                            | 结果           |
| ----------------------------- | -------------- |
| 挂在 `/auth/**`               | auth 服务 401  |
| 挂在 `/oauth2/**`             | 协议断裂       |
| Filter order 比 Security 还早 | 被 Security 拦 |
| 网关校验 JWT 合法性           | 重复校验       |
| 下游只信网关 Header           | 安全隐患       |

---

## ✅ 七、给你一个“使用口诀”（可以贴在团队 Wiki）

> 业务路由才挂 Filter
>
> 协议路由一律放行
>
> JWT 只解析不校验
>
> 黑名单留给资源服务器
