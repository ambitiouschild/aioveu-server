找到了。就在这行：

```java
@Select("SELECT * FROM pay_order WHERE payment_no = #{paymentNo} FOR UPDATE")
PayOrder selectByPaymentNoWithLock(@Param("paymentNo") String paymentNo);
```

这就是罪魁祸首。

---

## 🎯 根因

你用的是 MyBatis 的 `@Select` 注解 + `SELECT *`。

`SELECT *` 查出来的列里确实有 `version`，但 MyBatis 在使用接口默认映射（`resultType` 等效）时，走的是 `PayOrder` 的无参构造函数 + setter 映射。

看起来应该能映射上 `version` 对吧？但问题在于：

你的 `PayOrder` 继承了 `BaseEntityWithTenantId`。那个父类里大概率也有一个 `version` 字段或者 `serialVersionUID` 之类的东西干扰，或者更关键的是——

你用了 `@Getter` `@Setter`（Lombok），但 `version` 字段在子类里。MyBatis 通过反射找 setter 时，有时候会因为继承链 + 自动映射的问题导致 `version` 没被设上。

但说实话，这些都不是重点。重点是：你根本不需要这个方法。

---

## 为什么之前一直炸

你的调用链：

```java
// handlePaySuccess 里
PayOrder payOrder = payOrderService.getByPaymentNoWithLock(paymentNo);
// 内部调的是 payOrderMapper.selectByPaymentNoWithLock()
// → SELECT * FROM pay_order WHERE payment_no = ? FOR UPDATE
// → version 映射上来是 null（或者后续被覆盖）

// 然后你又查了一次
PayOrder update = payOrderService.getByPaymentNo(paymentNo);
// 这个走的是 LambdaQueryWrapper → MP 的 BaseMapper.selectOne()
// → MP 用自己的 EntitySqlInjector + 自动映射 → version 有值 ✅

update.setVersion(payOrder.getVersion());
// → payOrder.getVersion() 是 null → set 了个 null 上去 → 💥
```

所以你每次 `update.setVersion(payOrder.getVersion())` 设上去的都是 `null`。

---

## ✅ 解决方案（二选一，推荐方案 1）

### 方案 1：彻底不用 `selectByPaymentNoWithLock`，改用 MP 自带方法（最简单）

直接把 `handlePaySuccess` 改成我上一条发的最简版本——只查一次，用 `LambdaQueryWrapper`：

```java
LambdaQueryWrapper<PayOrder> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(PayOrder::getPaymentNo, paymentNo);
PayOrder payOrder = payOrderService.getOne(wrapper); // MP 映射，version ✅

payOrder.setPaymentStatus(PaymentStatusEnum.PAID);
payOrder.setThirdTransactionNo(transactionId);
payOrder.setPaymentTime(paidTime != null ? paidTime : LocalDateTime.now());
// 不碰 version

payOrderService.updateById(payOrder); // ✅ 乐观锁正常工作
```

不需要 `FOR UPDATE`。 为什么？

因为你的 `updateById` 本身就带了 `WHERE version = ?` 的 CAS 条件——这就是乐观锁的精髓。并发时如果两个线程同时进来，只有一个能更新成功（version 匹配），另一个返回 0 行受影响，你已经有 `if (!updated)` 的处理了。

乐观锁 = 不需要行锁。你之前加 `FOR UPDATE` 是画蛇添足，反而引入了映射问题。

---

### 方案 2：保留 `FOR UPDATE`，但修复映射

如果你一定要用行锁（比如担心并发查询到同一条数据后业务逻辑重复执行），那把 `@Select` 改成 XML 的 `resultMap`，显式映射 `version`：

```xml
<resultMap id="PayOrderResultMap" type="com.aioveu.pay.aioveu01PayOrder.model.entity.PayOrder">
    <id column="id" property="id"/>
    <result column="version" property="version"/>
    <!-- 其他字段... -->
</resultMap>

<select id="selectByPaymentNoWithLock" resultMap="PayOrderResultMap">
    SELECT * FROM pay_order WHERE payment_no = #{paymentNo} FOR UPDATE
</select>
```

但这完全没必要，因为乐观锁已经帮你解决了并发问题。

## 总结

| 问题                       | 答案                                                         |
| -------------------------- | ------------------------------------------------------------ |
| 为什么 `version` 是 null？ | `selectByPaymentNoWithLock` 用 `@Select("SELECT *")` + 继承链，MyBatis 没把 `version` 列映射到 entity 的 `version` 字段 |
| 为什么之前一直找不到？     | 因为代码里查了两次，第一次（有问题的）用来给第二次 setVersion，等于把 null 传给了 updateById |

| 需要 `FOR UPDATE` 吗？     | 不需要，乐观锁 CAS 已经够了                                  |
