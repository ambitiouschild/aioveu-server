## 三、问题不在 Job，而在「租户插件设计」

### ❌ 当前致命点（你这个 Job 的视角）

```java
@InterceptorIgnore(tenantLine = "true")
@Scheduled(cron = "0 */5 * * * ?")
public void reconcile() { ... }
```

你以为：

> “加了 `@InterceptorIgnore`，就不会走租户逻辑了”

但 MyBatis‑Plus 的真实行为是：

```
SQL 执行
 ↓
MybatisPlusInterceptor
 ↓
TenantLineInnerInterceptor.beforeQuery()
 ↓
buildTableExpression()
 ↓
handler.getTenantId()   ← ❗❗❗ 仍然会调用
```

即使：

• `tenantLine = true`

• SQL 最终不加 `tenant_id`


👉 `getTenantId()` 仍然会被调用
👉 你这里直接 `throw new IllegalStateException("租户上下文未初始化")`
👉 Job 必挂

## 四、✅ 正确修复方案（推荐顺序）

---

## ✅✅ 方案一（最推荐）：租户插件「区分 Job 与 Web」

### ✅ 核心思想

> Job 场景 ≠ Web 场景
>
> - Web：必须校验租户
> - Job：允许无租户（或兜底）

---

### ✅ 修改 `MyTenantLineHandler.getTenantId()`

```java
@Override
public Expression getTenantId() {
    String tenantId = TenantContextHolder.getTenantId();

    // ✅ Job / 平台级入口
    if (tenantId == null) {
        // 判断是否是 Job 线程
        if (isJobContext()) {
            log.debug("Job 场景，跳过租户过滤");
            return null; // ❗关键：返回 null，MP 不会拼 tenant_id
        }

        // ❌ Web 场景才严格报错
        throw new IllegalStateException(
            "租户上下文未初始化，Web 请求必须通过 Token 设置租户"
        );
    }

    return new StringValue(tenantId);
}
```

---

### ✅ Job 上下文识别（非常关键）

#### ✅ 方式一：ThreadLocal 标记（最稳）

```java
public class JobContext {

    private static final ThreadLocal<Boolean> JOB_FLAG =
            ThreadLocal.withInitial(() -> false);

    public static void setJob() {
        JOB_FLAG.set(true);
    }

    public static boolean isJob() {
        return JOB_FLAG.get();
    }

    public static void clear() {
        JOB_FLAG.remove();
    }
}
```

---

### ✅ 改造 Job（**你这个 Job 最终正确版**）

```java
@Scheduled(cron = "0 */5 * * * ?")
public void reconcile() {
    log.info("支付兜底Job开始执行");

    JobContext.setJob(); // ✅ 标记 Job 上下文
    try {
        LocalDateTime maxCreatedAt = LocalDateTime.now().minusMinutes(30);
        LocalDateTime lastCreatedAt = LocalDateTime.now();
        Long lastId = Long.MAX_VALUE;
        int batchSize = 200;

        while (true) {
            List<PayOrder> orders = payOrderMapper
                    .selectPendingOrdersForQuery(
                            maxCreatedAt,
                            lastCreatedAt,
                            lastId,
                            batchSize
                    );

            if (CollUtil.isEmpty(orders)) {
                break;
            }

            orders.forEach(o ->
                recoveryService.recover(o.getPaymentNo())
            );

            PayOrder last = orders.get(orders.size() - 1);
            lastId = last.getId();
            lastCreatedAt = last.getCreateTime();
        }

        log.info("支付兜底Job执行结束");
    } finally {
        JobContext.clear(); // ✅ 必须清
    }
}
```

✅ `@InterceptorIgnore` 可以保留，也可以删掉
✅ 推荐 保留，语义更明确

---

## ✅✅ 方案二（次优，但可用）：getTenantId() 直接兜底返回 null

如果你 明确 Job = 平台级、不按租户隔离：

```java
@Override
public Expression getTenantId() {
    String tenantId = TenantContextHolder.getTenantId();
    if (tenantId == null) {
        return null; // ✅ 不拼 tenant_id
    }
    return new StringValue(tenantId);
}
```

⚠️ 风险：  
如果某天 Web 请求忘了设租户，会悄无声息地查全表数据

👉 不推荐在多租户生产环境长期用

## ✅✅ 方案三（架构级，最优雅）：Job 专用数据源 / Mapper

• Job 用 非租户数据源

• Web 用 租户数据源


✅ 这是支付宝 / 微信支付级别的架构  
❌ 成本较高，一般中小系统不需要
