------

## 🎯 根因（一行话版）

> **MyBatis-Plus 乐观锁插件找不到 `version`字段的原始值，导致 SQL 执行时参数 `MP_OPTLOCK_VERSION_ORIGINAL`不存在，直接炸了。**

------

## 详细拆解

### 报错的核心（Cause 链最底部）：

```
Caused by: org.apache.ibatis.binding.BindingException: 
Parameter 'MP_OPTLOCK_VERSION_ORIGINAL' not found. 
Available parameters are [param1, et]
```

这是 **MyBatis-Plus 乐观锁插件（OptimisticLockerInnerInterceptor）** 在工作时报的错。

### 它在干什么？

你的 SQL 是：

```
UPDATE pay_order 
SET payment_status = ?, payment_time = ?, third_transaction_no = ?, version = ?, update_time = ?
WHERE id = ? AND version = ? AND tenant_id = 3
```

这个 `AND version = ?`就是乐观锁插件自动加的条件——**它需要用旧 version 值来做 CAS 比较**。

但它去取旧值的时候，发现 **entity 里的 `version`字段是 `null`**，于是拼不出 `MP_OPTLOCK_VERSION_ORIGINAL`这个参数 → 直接抛异常。

------

## 为什么会 version 为 null？

看你调用链：

```
PaymentServiceImpl.queryPaymentStatusByPaymentNo()
  → PayOrderSuccessHandlerServiceImpl.handlePaySuccess()
    → payOrderService.updateById(payOrder)   // ← 这里炸的
```

`handlePaySuccess`里你构建/拿到 `PayOrder`对象后，调用了 `updateById`。问题是：

**你传给 `updateById`的 `PayOrder`对象里，`version`字段没有被设值（是 null）。**

常见场景：

| 场景                                                         | 说明         |
| ------------------------------------------------------------ | ------------ |
| 你 `new PayOrder()`手动 set 了几个字段，但没 setVersion      | 最常见       |
| 你从微信回调/查询接口拿到数据，转成对象时 version 没映射过来 | 也很常见     |
| 你先 `getById()`查出来了，但中间经过 DTO 转换后又 new 了一个 entity，version 丢了 | 重构后容易出 |

------

## 怎么修？（3 种方式，选一个）

### ✅ 方式 1：update 之前先从 DB 查出完整 entity（最稳）

```
// handlePaySuccess 里
PayOrder payOrder = payOrderService.getById(payOrderId);  // ← 带 version
payOrder.setPaymentStatus(Paid);
payOrder.setPaymentTime(now);
payOrder.setThirdTransactionNo(thirdNo);
// 不要手动 setVersion！让 MP 自动处理
payOrderService.updateById(payOrder);
```

这样 `version`有值，乐观锁插件能正常工作。

------

### ✅ 方式 2：如果不需要乐观锁，临时关掉这个实体的乐观锁

在 `PayOrder`实体类里，把 `@Version`注解去掉，或者：

```
@TableField(fill = FieldFill.INSERT)  // 只在插入时管 version，更新不管
@Version
private Integer version;
```

或者更暴力的——在 `application.yml`里暂时把乐观锁插件注释掉（**不推荐生产**）。

------

### ✅ 方式 3：手动设 version（不推荐，容易出错）

```
PayOrder existing = payOrderService.getById(id);
payOrder.setVersion(existing.getVersion());  // 手动带上旧版本号
payOrderService.updateById(payOrder);
```

## 顺便提醒一个事

你之前在 `PmsSkuServiceImpl.lockStock()`里也用了类似的模式：

```
this.update(new LambdaUpdateWrapper<PmsSku>()
    .setSql("locked_stock = locked_stock + " + quantity)
    .eq(PmsSku::getId, skuId)
    .apply("stock - locked_stock >= {0}", quantity)
);
```

这种方式 **不走 `updateById`，不走乐观锁插件**，所以不会触发 `MP_OPTLOCK_VERSION_ORIGINAL`的问题。但如果你将来在 `pay_order`上也用 `updateById`却没带 version，就会一直踩这个坑。

## 总结

| 问题                                     | 答案                                                         |
| ---------------------------------------- | ------------------------------------------------------------ |
| 为什么微信查询异常？                     | `handlePaySuccess`里 `updateById(payOrder)`时 `payOrder.version = null` |
| 为什么报 `MP_OPTLOCK_VERSION_ORIGINAL`？ | MyBatis-Plus 乐观锁插件需要旧 version 值做 CAS，找不到就炸   |
| 怎么最快修？                             | `updateById`之前先 `getById()`查出完整 entity，再 set 你要改的字段 |
| 跟之前的网关/JWT 问题有关吗？            | 完全无关，这是纯后端 ORM 层的问题                            |
