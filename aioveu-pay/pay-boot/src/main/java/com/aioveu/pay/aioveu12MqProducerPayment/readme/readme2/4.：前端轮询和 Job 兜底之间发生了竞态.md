这个问题的本质是：**前端轮询和 Job 兜底之间发生了竞态，而且前端查到"已支付"后直接跳走了，没有触发 OMS 订单状态更新，Job 那边又被轮询的结果干扰了。**

让我理清链路，然后给你一套**正确且主流的解法**。

------

## 🔍 问题根因分析

你现在的链路：

```
用户支付成功 → 微信回调（本地测试收不到）
                ↓
         前端轮询（查 Pay 服务）→ 发现 paymentStatus = PAID
                ↓
         前端直接跳到 paySuccess 页
                ↓
         OMS 订单状态还是 UNPAID ← 💥 没人调 OMS 更新
```

同时 Job 兜底也想更新，但：

| 问题                     | 原因                  |
| ------------------------ | --------------------- |
| Job 查到订单已付         | 但 OMS 里还是 UNPAID  |
| 前端已经跳走             | 前端不会再管 OMS 的事 |
| Job 和前端轮询可能同时写 | 并发覆盖 / 乐观锁失败 |

**核心问题：谁来负责通知 OMS 更新订单状态？**

------

## ✅ 正确架构（主流做法）

```
微信回调（正式）/ 前端模拟（测试）
                            ↓
                    Pay 服务标记支付成功
                            ↓
                    【发 MQ 消息】← 这一步你缺了
                            ↓
                    OMS 消费 MQ → 更新订单状态
                            ↓
                    前端轮询 OMS 状态 → 看到 PAID → 跳转
```

**MQ 才是连接 Pay → OMS 的正确桥梁，不是前端直接跳。**

------

## 🔧 你现在本地测试的完整解法

既然微信回调收不到，你需要一个**手动触发/前端触发**的机制来模拟微信回调做的事。

### 方案一：前端轮询到支付成功后，主动调一个接口通知 OMS（推荐）

**前端轮询逻辑改成：**

```
const pollOrderStatus = async (orderSn: string) => {
  const timer = setInterval(async () => {
    try {
      // 1. 查支付状态（Pay 服务）
      const payRes = await PayAPI.queryOrder(orderSn);

      if (payRes.paid) {
        clearInterval(timer);

        // 2. ★ 关键：通知 OMS 更新订单状态
        await OmsOrderDetailAPI.notifyPaymentSuccess(orderSn, payRes.transactionId);

        // 3. 再查一次 OMS 确认状态已更新
        const omsRes = await OmsOrderDetailAPI.getOmsOrderDetail(orderSn);
        if (omsRes.status === OrderStatusEnum.PAID) {
          // 4. 跳转成功页
          uni.redirectTo({
            url: `/packageD/pages/money/paySuccess?orderSn=${orderSn}&amount=${payRes.amount}`,
          });
        }
      }
    } catch (e) {
      console.error('轮询异常', e);
    }
  }, 2000);

  setTimeout(() => clearInterval(timer), 5 * 60 * 1000);
};
```

**后端新增一个接口（模拟微信回调的核心逻辑）：**

```
// Controller
@PostMapping("/notify/payment-success")
public Result<Void> notifyPaymentSuccess(@RequestBody PaymentNotifyDTO dto) {
    orderService.handlePaymentSuccess(dto.getOrderSn(), dto.getTransactionId());
    return Result.success();
}

// DTO
@Data
public class PaymentNotifyDTO {
    private String orderSn;
    private String transactionId;
}
```

**Service 里处理（跟微信回调共用同一段逻辑）：**

```
@Override
@Transactional(rollbackFor = Exception.class)
public void handlePaymentSuccess(String orderSn, String transactionId) {
    Long tenantId = SecurityUtils.getTenantId();

    // 查询订单
    OmsOrder order = this.baseMapper.selectOne(
            Wrappers.<OmsOrder>lambdaQuery()
                    .eq(OmsOrder::getOrderSn, orderSn)
                    .eq(OmsOrder::getTenantId, tenantId)
    );

    if (order == null) {
        throw new BusinessException("订单不存在");
    }

    // 已经付过了，幂等返回
    if (OrderStatusEnum.PAID.getCode().equals(order.getStatus())) {
        log.info("订单已支付，幂等跳过, orderSn={}", orderSn);
        return;
    }

    // 校验必须是待付款
    if (!OrderStatusEnum.UNPAID.getCode().equals(order.getStatus())) {
        throw new BusinessException("订单状态异常，无法标记为已支付");
    }

    // 更新订单状态
    OmsOrder updateEntity = new OmsOrder();
    updateEntity.setId(order.getId());
    updateEntity.setStatus(OrderStatusEnum.PAID.getCode());
    updateEntity.setPaymentTime(LocalDateTime.now());
    updateEntity.setTransactionId(transactionId);
    updateEntity.setUpdateTime(LocalDateTime.now());

    int rows = this.baseMapper.update(
            updateEntity,
            Wrappers.<OmsOrder>lambdaUpdate()
                    .eq(OmsOrder::getId, order.getId())
                    .eq(OmsOrder::getStatus, OrderStatusEnum.UNPAID.getCode())
                    .eq(OmsOrder::getTenantId, tenantId)
    );

    if (rows == 0) {
        throw new BusinessException("订单状态更新失败，请重试");
    }

    log.info("订单支付成功，状态已更新, orderSn={}, transactionId={}", orderSn, transactionId);

    // ★ 发 MQ 通知后续业务（库存扣减、积分、消息推送等）
    // mqSender.sendOrderPaidEvent(orderSn, transactionId);
}
```

### 方案二：前端轮询直接查 OMS，OMS 内部去查 Pay 服务（更简单）

**把"查 Pay"和"更新 OMS"两步合到 OMS 的一个接口里：**

```
// Controller
@GetMapping("/query-and-update-status")
public Result<OrderStatusVO> queryAndUpdateStatus(@RequestParam String orderSn) {
    OrderStatusVO vo = orderService.queryAndUpdateFromPay(orderSn);
    return Result.success(vo);
}
@Override
public OrderStatusVO queryAndUpdateFromPay(String orderSn) {
    // 1. 先查 OMS 本地状态
    OmsOrder order = getOrderBySn(orderSn);
    
    // 2. 如果已经是 PAID，直接返回（幂等）
    if (OrderStatusEnum.PAID.getCode().equals(order.getStatus())) {
        return buildVO(order);
    }

    // 3. 调 Pay 服务查支付结果
    PayQueryResult payResult = payFeignClient.queryOrder(orderSn);
    
    // 4. 如果 Pay 服务说已付 → 更新 OMS
    if (payResult.isPaid()) {
        handlePaymentSuccess(orderSn, payResult.getTransactionId());
    }

    // 5. 返回最新状态
    OmsOrder latest = getOrderBySn(orderSn);
    return buildVO(latest);
}
```

**前端轮询只调 OMS 这一个接口：**

```
const pollOrderStatus = (orderSn: string) => {
  const timer = setInterval(async () => {
    try {
      const res = await OmsOrderDetailAPI.queryAndUpdateStatus(orderSn);
      
      if (res.status === OrderStatusEnum.PAID.getCode()) {
        clearInterval(timer);
        uni.redirectTo({
          url: `/packageD/pages/money/paySuccess?orderSn=${orderSn}&amount=${res.paymentAmount}`,
        });
      }
    } catch (e) {
      console.error(e);
    }
  }, 2000);
};
```

## 📋 两种方案对比

| 对比项           | 方案一（前端通知 OMS） | 方案二（OMS 自查 Pay） |
| ---------------- | ---------------------- | ---------------------- |
| 前端复杂度       | 多一步调用             | 只调一个接口 ✅         |
| 后端职责         | OMS 被动接收           | OMS 主动查 Pay ✅       |
| 跟正式链路一致性 | 完全一致（MQ 驱动）    | 测试用，正式还是 MQ    |
| 并发安全         | 乐观锁                 | 乐观锁                 |
| 推荐度           | ⭐⭐⭐⭐⭐（正式）          | ⭐⭐⭐⭐⭐（测试）          |

## 🔑 你现在最该做的事

**用方案二**，因为：

1. 

   你本地测试没有微信回调

2. 

   前端轮询只关心"OMS 里订单是不是 PAID 了"

3. 

   OMS 自己负责去 Pay 服务确认并更新状态

4. 

   前端不用管"谁来更新 OMS"这个问题

等你部署到测试/生产环境，微信回调通了之后，把方案二的轮询接口**关掉**（或保留做兜底），正式流量走 MQ → OMS 消费。

## ⚠️ Job 兜底怎么不被覆盖？

Job 的逻辑应该是：

```
// Job 定时任务
@Scheduled(cron = "0 */1 * * * ?")
public void checkUnpaidOrders() {
    List<OmsOrder> unpaidOrders = this.baseMapper.selectList(
            Wrappers.<OmsOrder>lambdaQuery()
                    .eq(OmsOrder::getStatus, OrderStatusEnum.UNPAID.getCode())
                    .lt(OmsOrder::getCreateTime, LocalDateTime.now().minusMinutes(30))
                    .eq(OmsOrder::getDeleted, 0)
    );

    for (OmsOrder order : unpaidOrders) {
        try {
            // 查 Pay 服务
            PayQueryResult payResult = payFeignClient.queryOrder(order.getOrderSn());
            if (payResult.isPaid()) {
                handlePaymentSuccess(order.getOrderSn(), payResult.getTransactionId());
            } else {
                // 超过30分钟还没付 → 取消
                cancelOrder(order.getOrderSn());
            }
        } catch (Exception e) {
            log.error("Job 处理订单失败, orderSn={}", order.getOrderSn(), e);
        }
    }
}
```

**关键是 `handlePaymentSuccess`里的乐观锁**——不管是前端触发的方案二、还是 Job、还是未来的微信回调，都走同一个方法，靠 `WHERE status = UNPAID`保证只有一个能成功，其余幂等跳过。

## 总结一句话

> **前端轮询不应该只"查"，应该"查+触发更新"。最干净的做法是：前端轮询 OMS 的一个接口，OMS 内部查 Pay → 更新自己 → 返回最新状态。这样 Job 和前端永远不会互相覆盖。**
