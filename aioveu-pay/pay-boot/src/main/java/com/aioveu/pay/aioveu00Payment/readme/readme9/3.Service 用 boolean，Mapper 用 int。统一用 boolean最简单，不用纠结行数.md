这是 MyBatis-Plus 的 `updateById` 返回类型是 `boolean`，不是 `int`。你代码里写了：

```java
int rows = payOrderService.updateById(update);
```

改成这样就行：

```java
boolean updated = payOrderService.updateById(update);
if (!updated) {
    log.warn("【支付失败处理】并发冲突, paymentNo={}", paymentNo);
    return;
}
```

---

或者如果你想要 `int` 行数（比如后面要做精确判断），那就绕过 Service 直接调 Mapper：

```java
int rows = payOrderMapper.updateById(update);  // Mapper 返回 int
if (rows == 0) {
    log.warn("【支付失败处理】并发冲突, paymentNo={}", paymentNo);
    return;
}
```

---

## 原因

| 调用方式                             | 返回类型  | 说明                        |
| ------------------------------------ | --------- | --------------------------- |
| `payOrderService.updateById(update)` | `boolean` | MP 的 `IService` 接口定义   |
| `payOrderMapper.updateById(update)`  | `int`     | Mapper 层直接返回受影响行数 |

你之前在 `updateStatusIfNonTerminal` 里用的是 Mapper 直接调 SQL，所以返回 `int` 没问题。但在 `PayOrderSuccessHandler` 里调的是 Service 层的 `updateById`，就得用 `boolean`。

---

## 顺便提醒

你之前那个 `updateLocalStatus` 方法里也有同样的问题：

```java
// 你原来的
int rows = payOrderMapper.updateStatusIfNonTerminal(...);  // ✅ mapper 直接调，返回 int，没问题
```

这个是对的，因为那是 Mapper 不是 Service。

总结：Service 用 `boolean`，Mapper 用 `int`。统一用 `boolean` 最简单，不用纠结行数。 👍
