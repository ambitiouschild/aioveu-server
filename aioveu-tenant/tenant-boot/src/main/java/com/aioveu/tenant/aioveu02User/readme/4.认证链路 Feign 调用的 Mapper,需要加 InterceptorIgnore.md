## 二、为什么是 Mapper，不是 Controller？

因为：

• MP 的租户插件拦截的是 SQL

• SQL 是在 Mapper 执行时拼的

• Controller / Feign 层早就过了


所以正确层级是：

```
Feign
 ↓
Controller
 ↓
Service
 ↓
Mapper ✅ ← 在这里关 MP
 ↓
SQL
```

## 三、你现在最该加的地方（对照你之前的代码）

### ✅ 正确位置 ✅

```java
@InterceptorIgnore(tenantLine = "true")
List<String> listRolePermsWithTenantId(
        @Param("params") Map<String, Object> params
);
```

或者你新写的这个：

```java
@InterceptorIgnore(tenantLine = "true")
@MapKey("roleCode")
Map<String, Set<String>> listRolePermsGroupByRoleWithTenantId(
        @Param("params") Map<String, Object> params
);
```

✅ 一个注解就够了
✅ SQL 里你已经有 `tenant_id = #{params.tenantId}`
✅ MP 再拼就是重复 / 错误

---

## 四、为什么“必须加”，而不是“算了不管”

如果不加：

• MP 仍然会走 `TenantLineHandler`

• 虽然你 SQL 里写了 `tenant_id`

• 但 MP 可能再拼一次

• 极端情况：

  • `tenant_id = 3 AND tenant_id = null`

  • 或者直接抛异常


👉 你现在这套是“参数驱动”，不是“MP 驱动”
👉 所以 MP 必须“闭嘴”

---

## 五、一个非常重要的“架构级认知”

> `@InterceptorIgnore` 不是“偷懒”
>
> ✅ 它是“声明：这个 SQL 的租户逻辑我自行负责”

你加这个注解，语义是：

> “这个 Mapper 方法：
> - 不参与 MP 的租户自动拼接
> - 租户条件由我显式控制
> - 用于认证 / 内部链路”

👉 这是专业用法
👉 不是 hack

---

## 六、哪些接口需要加？（给你一个清单）

✅ 需要加 `@InterceptorIgnore(tenantLine = "true")` 的：

• 认证链路 Feign 调用的 Mapper

• 手动拼 `tenant_id` 的 SQL

• `listRolePermsGroupByRoleWithTenantId`

• `listRolePermsWithTenantId`


❌ 不需要加的：

• 普通业务 Mapper

• 用户登录后请求的接口

• 依赖 ThreadLocal 的查询

## 七、一个“防坑提示”（很重要）

### ❌ 不要加在类上

```java
@InterceptorIgnore(tenantLine = "true")
public interface RoleMenuMapper
```

除非你整个 Mapper 都是认证专用

否则会影响业务方法。

✅ 只加在方法上，精准打击
