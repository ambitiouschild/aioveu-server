## 一、你现在这套“绕路”的本质


但实际上你的表结构是：

```
sys_user
├── id
├── username

```

✅ 中间两步完全多余

## 二、最正确的 SQL（一次性到位）

### ✅ Mapper 直接 JOIN

```java
@Select("""
    SELECT
        t.id,
        t.name,
        t.status
    FROM sys_user u
    JOIN sys_tenant t ON u.tenant_id = t.id
    WHERE u.username = #{username}
      AND u.is_deleted = 0
      AND t.is_deleted = 0
      AND t.status = 1
""")
List<TenantVO> getAccessibleTenantsByUsername(String username);
```

### ✅ 为什么这是对的

| 维度       | 说明              |
| ---------- | ----------------- |
| SQL 次数   | ✅ 1 次            |
| 网络 IO    | ✅ 最少            |
| 内存计算   | ✅ 无              |
| 可维护性   | ✅ 极高            |
| 语义清晰度 | ✅ “用户名 → 租户” |

```java
@PublicApi(description = "根据用户名获取可登录的租户列表")
@GetMapping("/tenants/{username}")
public Result<List<TenantVO>> getAccessibleTenantsByUsername(
        @PathVariable String username) {

    List<TenantVO> tenantList =
            tenantService.getAccessibleTenantsByUsername(username);

    log.info("[跨租户][平台接口] 用户 '{}' 可访问 {} 个租户: {}",
            username,
            tenantList.size(),
            tenantList.isEmpty()
                    ? "无"
                    : tenantList.stream()
                            .map(t -> t.getId() + ":" + t.getName())
                            .collect(Collectors.joining(", ", "[", "]")));

    return Result.success(tenantList);
}
```
