## 三、为什么“那些方法靠 MP 过滤”现在成了问题？

因为你在**两个不同的世界观**里写代码：

| 场景           | 租户来源                 |
| -------------- | ------------------------ |
| 用户请求       | TenantContextHolder      |
| Feign 认证调用 | 方法参数                 |
| MP             | 只认 TenantContextHolder |

👉 **当 Feign 调用发生时，世界观崩塌了**

## 四、你现在面临的不是一个 Bug，而是一个“架构选择”

你现在只有三条路，**没有第四条**：

------

### ❌ 路线 A：继续幻想 MP 能自动工作（不可行）

> “我能不能在 Feign 调用时，把 tenantId 塞进 MP？”

我们已经证明：

- 

  ❌ 时机晚

- 

  ❌ 会污染线程

- 

  ❌ 会和忽略表冲突

- 

  ❌ 会串租户

👉 **这条路在架构层面就堵死了**

------

### ✅✅✅ 路线 B（推荐）：**认证链路“脱离 MP”**

> **认证接口 = 参数驱动**
>
> **业务接口 = MP 驱动**

#### 改造点（非常现实）：

##### ① 这个接口 + 相关查询，**全部加 tenantId 参数**

```
List<RoleDataScope> getRoleDataScopes(
    Set<String> roles,
    Long tenantId);

Set<String> getRolePermsByRoleCodes(
    Set<String> roles,
    Long tenantId);
```

##### ② Mapper XML 手写 tenant_id

```
AND r.tenant_id = #{tenantId}
```

##### ③ Controller 关闭 MP

```
@InterceptorIgnore(tenantLine = "true")
```

✅ **一次性解决**

✅ **逻辑清晰**

✅ **不污染业务代码**

👉 **这是大多数中大型系统的真实选择**

------

### ⚠️ 路线 C：让 Feign 调用“假装是用户请求”（不推荐）

比如：

- 

  Feign 里带 JWT

- 

  Filter 里 setTenantId

- 

  所有方法继续无参数

问题：

- 

  ❌ 认证接口走 JWT，语义混乱

- 

  ❌ token 过期怎么办？

- 

  ❌ client_credentials vs user token

- 

  ❌ 后期审计灾难

👉 **短期能跑，长期必还债**

## 五、一个非常现实的“认知升级”

你现在的痛苦，本质是：

> **“我想用 MP 的便利，但又不想接受 MP 的前提条件。”**

MP 的前提条件是：

> ✅ **请求必须有 TenantContext**
>
> ✅ **请求必须是“用户请求”**

而你现在这个是：

> ❌ **Feign**
>
> ❌ **无 JWT**
>
> ❌ **认证阶段**

👉 **不是 MP 不够强**

👉 **是这个场景不在 MP 的设计范围内**
