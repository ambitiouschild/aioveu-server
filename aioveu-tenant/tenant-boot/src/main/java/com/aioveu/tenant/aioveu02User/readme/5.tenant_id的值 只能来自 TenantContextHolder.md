## 二、你这个场景下的“唯一正确写法”

```
public UserAuthCredentials getAuthInfo(String username, Long tenantId) {
    try {
        // ✅ 明确告诉 MP：这次 SQL 用哪个租户
        TenantContextHolder.setTenantId(tenantId);

        return baseMapper.getAuthInfoByUsernameAndTenantId(username);
    } finally {
        // ✅ 登录接口专用：立刻清理，不影响后续线程
        TenantContextHolder.clear();
    }
}
```

### Mapper 对应改成：

```
@InterceptorIgnore(tenantLine = "true")
UserAuthCredentials getAuthInfoByUsernameAndTenantId(
        @Param("username") String username
);
```

✅ XML 里 **仍然手写 `tenant_id = #{xxx}`**

✅ MP 不追加

✅ MP 不替换

✅ 值来自 Context

✅ 参数只是“语义存在”

------

## 三、为什么这是“最不坏 + 最安全”的方案

### ✅ 优点

- 

  ✅ `sys_user`不进 ignore-tables

- 

  ✅ 业务接口继续享受 MP 自动租户

- 

  ✅ 登录接口行为可预期

- 

  ✅ 不引入“伪参数驱动”的错觉

### ⚠️ 代价（必须承认）

- 

  ❌ 登录接口依赖 ThreadLocal

- 

  ❌ 必须 `try-finally`

- 

  ❌ 不是“纯参数驱动”

👉 **但这些代价，在“不 ignore sys_user”的前提下，是必须付的**
