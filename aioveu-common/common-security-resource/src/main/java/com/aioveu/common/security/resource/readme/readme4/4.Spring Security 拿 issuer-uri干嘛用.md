## ✅ 一句话人话版

> `issuer-uri` 就是：
>
> 👉 “这个 JWT 是哪个认证服务发的”
>
> 👉 资源服务器用它来判断：我该不该信这个 Token

## 二、`iss` 和 `issuer-uri` 的关系（必须分清）

### ✅ JWT 里的 `iss` 声明（payload 里）

你贴过的 JWT 里就有：

```json
"iss": "http://192.168.1.3:9000"
```

这表示：

> ✅ 这个 Token 是 `http://192.168.1.3:9000` 这个认证服务签发的

---

### ✅ `issuer-uri` 是 **资源服务器侧的配置**

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: http://192.168.1.3:9000
```

它的含义是：

> ✅ 我只认“由这个地址签发的 JWT”
>
> ❌ 别的 iss 一律拒绝

---

## 三、Spring Security 拿 `issuer-uri` 干嘛用？

### ✅ 如果你配了 `issuer-uri`，Spring 会：

1. 校验 JWT 里的 `iss` 必须等于 `issuer-uri`
2. 自动发现 OIDC 配置（可选）
3. 在某些版本里，还会帮你推断 `jwk-set-uri`

### ❌ 如果你没配 `issuer-uri`：

• ✅ JWT 仍然可以验签

• ✅ 只要公钥能拿到

• ❌ Spring 不会帮你校验 `iss`

## 四、为什么你刚才直接炸了？

因为你写了这段代码：

```java
new JwtIssuerValidator(props.getJwt().getIssuerUri())
```

而 `getIssuerUri()` 是 null，于是：

```text
IllegalArgumentException: issuer cannot be null
```

⚠️ 注意：

| 配置                 | 是否必须           |
| -------------------- | ------------------ |
| `jwk-set-uri`        | ✅ 必须（验签用）   |
| `issuer-uri`         | ❌ 可选             |
| `JwtIssuerValidator` | ❌ 必须 issuer 非空 |

👉 你“手动启用 issuer 校验”，但没给它值

## 五、你这个架构里，`issuer-uri` 到底要不要配？

### ✅ 你的真实情况是：

• ✅ 有统一认证服务（Authorization Server）

• ✅ JWT 里已经有 `iss`

• ✅ 多微服务共用资源服务器 jar

• ✅ 网关统一入口

• ✅ 不希望每个微服务都管 issuer


👉 结论：

> ❌ 不建议你在 yml 里配 `issuer-uri`
>
> ✅ 直接在代码里不校验 issuer 是最优解

## 六、✅ 推荐你最终用的“正确姿势”

### ✅ 只校验签名 + 有效期（你现在的最优解）

```java
@Bean
public JwtDecoder jwtDecoder(OAuth2ResourceServerProperties props) {

    return NimbusJwtDecoder
            .withJwkSetUri(props.getJwt().getJwkSetUri())
            .build();
}
```

或者更明确一点：

```java
@Bean
public JwtDecoder jwtDecoder(OAuth2ResourceServerProperties props) {

    NimbusJwtDecoder decoder = NimbusJwtDecoder
            .withJwkSetUri(props.getJwt().getJwkSetUri())
            .build();

    // ✅ 只校验时间，不校验 issuer / aud
    decoder.setJwtValidator(new JwtTimestampValidator());
    return decoder;
}
```

✅ 启动一定过
✅ `/me` 一定通
✅ 不依赖额外配置
✅ 多环境友好

## 七、什么时候「必须」配 `issuer-uri`？

只有在下面这些情况之一成立时：

✅ 你是 OIDC 标准系统
✅ 需要 自动发现 JWK / OIDC 配置
✅ 安全要求极高（iss 必须白名单）
✅ 单租户、单认证源

👉 你这套 SaaS / 多微服务架构，不属于这种情况

## 八、一句话把这件事彻底说清

> ❌ `issuer-uri` 不是 JWT 验签必须的
>
> ❌ `issuer-uri` 不是 JWK 发现的必要条件
>
> ✅ `issuer-uri` 只是“我信哪个签发者”的声明
>
> ✅ 你现在的架构：不配、不校验，是最干净的做法
