# 一、先给结论（很重要）

### ✅ 主流设计里：

> **TenantFilter / TenantInterceptor**
>
> ✅ **只认 Authentication / JWT**
>
> ❌ **不配“URL 白名单”**
>
> ❌ **不识别 clientId / appId / 公共请求**

**白名单如果存在，一定在：**

- 

  Spring Security 的 `SecurityFilterChain`

- 

  或 Gateway 层

- 

  **而不是在租户解析 Filter 里**

# 二、主流微服务体系里，是怎么做的？

## ✅ 主流模型（OAuth2 / OIDC / Spring Cloud 通用）

### 1️⃣ 请求分类由 Security 决定（不是 Filter）

```
http
    .securityMatcher("/api/**")
    .authorizeHttpRequests(auth -> auth
        .requestMatchers(
            "/api/public/**",
            "/api/v8/app/**",
            "/api/v8/admin/tenant/users/tenants/**"
        ).permitAll()
        .anyRequest().authenticated()
    )
    .oauth2ResourceServer(oauth2 -> ...);
```

✅ **Security 决定：**

- 

  这个请求要不要 JWT

- 

  这个请求能不能匿名

------

### 2️⃣ Filter 只干“单一职责”

| Filter                           | 认什么                   | 不认什么 |
| -------------------------------- | ------------------------ | -------- |
| `ClientIdTenantResolutionFilter` | clientId                 | JWT      |
| `TenantFilter`                   | `JwtAuthenticationToken` | clientId |
| `JwtBlacklistFilter`             | JWT                      | 匿名请求 |

✅ **Filter 不判断 URL**

✅ **Filter 不决定“是否放行”**

✅ **Filter 只解析、不裁决**

------

### 3️⃣ 公共请求 ≠ 租户请求（这是关键认知）

在主流设计里：

- 

  `/app/**`→ **可能连租户都不需要**

- 

  `/public/**`→ **可能直接走独立 FilterChain**

- 

  `/admin/**`→ **必须有 JWT**

👉 **不会让同一个 TenantFilter 去兼容“JWT + 公共接口”**

------

# 三、那「在 TenantFilter 加白名单」主流吗？

## ❌ 不主流

## ⚠️ 而且是**反模式**

### 为什么？

### 1️⃣ 破坏了“单一职责”

`TenantFilter`的职责是：

> **从 JWT 里解析 tenantId**

一旦你加了：

```
if (uri.startsWith("/admin/tenant/users/tenants/")) {
    return;
}
```

你就悄悄引入了第二职责：

> **“我还负责判断这个 URL 要不要租户”**

❌ 这会让 Filter 变成：

- 

  既解析

- 

  又裁决

- 

  又和业务语义耦合

------

### 2️⃣ URL 白名单 = 架构债务

你自己在注释里都写过：

> ❌ URL 是路由，不是语义

而主流架构非常忌讳：

- 

  `/admin/**`有的地方要 JWT，有的地方不要

- 

  Filter 靠字符串判断业务边界

**三个月后没人敢改 URL**

------

### 3️⃣ 白名单解决不了“身份问题”

即使你加了白名单：

```
shouldNotFilter = true
```

你也只是：

> ✅ 不抛异常了
>
> ❌ 但没有解决：
>
> - 
>
>   这个请求到底是谁
>
> - 
>
>   有没有租户
>
> - 
>
>   能不能被信任

**白名单只是“别报错”，不是“合法化”**

# 六、那“主流 + 正确”的做法到底是什么？

## ✅ 正确做法（你现在已经在门口了）

### ✅ 方案一（最主流、最推荐）

**TenantFilter 永远不加白名单**

```
@Override
protected boolean shouldNotFilter(HttpServletRequest request) {
    return request.getAttribute("__PUBLIC_CLIENT_REQUEST__") != null;
}
```

✅ 这个 attribute：

- 

  不是 URL

- 

  不是配置

- 

  不是业务语义

- 

  是 **Filter 之间的技术契约**

👉 **这是主流架构里最常见的“内部信号”机制**

------

### ✅ 方案二（更接近云原生主流）

**按请求类型拆 SecurityFilterChain**

```
@Bean
SecurityFilterChain publicChain(
        HttpSecurity http
) throws Exception {
    http
        .securityMatcher("/api/v8/app/**", "/api/v8/admin/tenant/users/tenants/**")
        .authorizeHttpRequests(a -> a.anyRequest().permitAll())
        .addFilterBefore(new ClientIdTenantResolutionFilter(...), UsernamePasswordAuthenticationFilter.class);
    return http.build();
}
@Bean
SecurityFilterChain apiChain(
        HttpSecurity http
) throws Exception {
    http
        .securityMatcher("/api/**")
        .authorizeHttpRequests(a -> a.anyRequest().authenticated())
        .oauth2ResourceServer(...)
        .addFilterAfter(new TenantFilter(...), BearerTokenAuthenticationFilter.class);
    return http.build();
}
```

✅ **这是 Spring Security 5.7+ 的主流方向**

✅ **但复杂度高，你现阶段没必要**
