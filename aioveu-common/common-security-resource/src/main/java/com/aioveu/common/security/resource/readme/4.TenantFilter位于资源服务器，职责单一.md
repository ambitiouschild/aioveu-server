## ✅ 你现在这套的“正确数据流向”（画给你看）

### ✅ 1️⃣ Auth Server（认证阶段）

```
前端
 ↓
Gateway
 ↓
Auth Server
   ├─ 从 Header / JWT / 默认规则 解析 tenantId
   ├─ TenantContextHolder.setTenantId(tenantId)   // ✅ Auth Server 自己用
   ├─ Feign 调用 Tenant Service（显式传 tenantId）
   ├─ JWT 写入 tenant_id
   └─ 返回 access_token
```

👉 Auth Server 的 tenantId：
• ✅ 自己解析

• ✅ 自己用

• ✅ 自己传给下游

• ❌ 不从 Resource Server 拿


---

### ✅ 2️⃣ Resource Server（业务请求阶段）

```
前端
 ↓
Gateway
 ↓
Resource Server
   ├─ Spring Security 解析 JWT
   ├─ JwtSecurityUtils.getTenantId() ✅
   ├─ TenantFilter.doFilterInternal()
   │     └─ TenantContextHolder.setTenantId(tenantId) ✅
   ├─ 业务代码 / MP / 审计 / 日志 使用 TenantContextHolder
   └─ finally: TenantContextHolder.clear()
```

👉 Resource Server 的 tenantId：
• ✅ 来自 JWT

• ✅ 来自 Security Context

• ✅ 不依赖 Auth Server

• ✅ 不反向调用 Auth Server

## ✅ 一个非常重要的“认知澄清”

### ❌ 错误理解（很多人会这么想）

> Auth Server → Resource Server → Tenant Service  
> （tenantId 像接力棒一样传）

### ✅ 正确理解（你现在这套）

```
Auth Server ──→ Tenant Service
     │
     │ JWT
     ▼
Resource Server
```

👉 tenantId 有两个“独立源头”：
1. Auth Server（认证时）
2. JWT（业务请求时）

👉 它们不互相传递 tenantId
👉 它们只信任 JWT

## ✅ 那 `TenantFilter` 在 Resource Server 里到底“服务于谁”？

### ✅ 它服务的不是 MP（MyBatis Plus）

你说得非常对：

> MyBatis-Plus 的 TenantLineHandler 不会用 TenantContextHolder

MP 通常是这样：

```java
public Long getTenantId() {
    return JwtSecurityUtils.getTenantId();
}
```

✅ MP 直接读 JWT
✅ 不读 ThreadLocal

---

### ✅ 那 TenantFilter 服务于谁？

✅ 业务代码
✅ 日志 / 审计
✅ 非 MP 的 SQL
✅ 缓存 key
✅ 消息队列
✅ 灰度 / 路由

```java
Long tenantId = TenantContextHolder.getTenantId();
```

👉 它是“便利工具”，不是“权威来源”

## ✅ 你这个 `TenantFilter` 的一个小建议（不是必须）

### ✅ finally 里建议还是清一下（更安全）

```java
finally {
    TenantContextHolder.clear();
}
```

理由：
• Web 容器线程复用

• 异常中断时可能漏清

• 不影响 MP（MP 不读它）


但你说：

> 由 TenantInterceptor 负责清理

✅ 如果你们有统一 Interceptor 清理，那是更优设计
✅ 那这行注释可以保留

## ✅ 一句话最终总结（你可以写在架构文档里）

> `TenantFilter` 位于资源服务器，职责单一：从 Spring Security Context（JWT）中解析租户 ID 并设置到 `TenantContextHolder`，供业务代码、日志、审计等非 ORM 层使用；Auth Server 在认证阶段独立解析租户 ID，并通过 Feign 显式传递至租户服务，二者互不依赖；JWT 是所有服务的唯一租户权威来源。
