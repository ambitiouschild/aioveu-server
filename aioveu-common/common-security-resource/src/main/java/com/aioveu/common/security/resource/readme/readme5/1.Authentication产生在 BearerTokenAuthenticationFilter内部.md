## 二、精确发生时点（按源码级顺序）

### ✅ `BearerTokenAuthenticationFilter#doFilterInternal` 内部流程

```text
1️⃣ 从 request 里拿 Authorization: Bearer xxx
2️⃣ 调用 AuthenticationManager.authenticate()
3️⃣   → JwtAuthenticationProvider.authenticate()
4️⃣     → JwtDecoder.decode()          // 验签、解析 JWT
5️⃣     → JwtAuthenticationConverter    // 转成 JwtAuthenticationToken
6️⃣ Authentication 对象诞生 ✅
7️⃣ SecurityContextHolder.setAuthentication(authentication)
8️⃣ filterChain.doFilter()  // 👈 后面所有 Filter 都能拿到
```

👉 Authentication 是在第 6 步“就地诞生”的

## 三、那“前后”到底怎么定义？（你这个问题的本质）

### ✅ 按 Filter 链顺序看：

```text
Filter A
Filter B
BearerTokenAuthenticationFilter   ← ✅ Authentication 在这里产生
Filter C
Filter D
```

### ✅ 所以结论是：

| 位置                                   | Authentication 是否存在 |
| -------------------------------------- | ----------------------- |
| `BearerTokenAuthenticationFilter` 之前 | ❌ 不存在                |
| `BearerTokenAuthenticationFilter` 内部 | ✅ 产生                  |
| `BearerTokenAuthenticationFilter` 之后 | ✅ 存在                  |

## 六、最关键的那个“开关”（你一直踩中的点）

### ✅ `BearerTokenAuthenticationFilter` **不是一定会创建 Authentication**

它内部逻辑是：

```java
if (请求需要认证) {
    authentication = authenticate();
    SecurityContextHolder.setAuthentication(authentication);
} else {
    // permitAll / anonymous
    // 什么都不做
}
```

### ✅ “请求是否需要认证”的唯一判定者是：

```java
authorizeHttpRequests()
```

## 七、所以你这个问题的最终答案是这样的：

> ❓ Authentication 产生在 `BearerTokenAuthenticationFilter` 之前还是之后？

### ✅ 官方、准确、无歧义答案：

> ✅ Authentication 在 `BearerTokenAuthenticationFilter` 内部产生
>
> ✅ 在它调用 `filterChain.doFilter()` 之前
>
> ❌ 不可能在它之前存在
> ❌ 只有在它之后才能被其他 Filter 看到

---

## 八、那你的 `TenantFilter` 应该放在哪？（最终结论）

### ✅ 你这个 `TenantFilter` 的语义是：

> “我必须从 JWT 里拿 tenantId”

👉 那它必须放在：

```java
.addFilterAfter(tenantFilter, BearerTokenAuthenticationFilter.class)
```

❌ 放在之前 = 永远拿不到
✅ 放在之后 = 100% 稳定

---

## 九、但为什么你之前那些 Filter 能“放在之前”？

| Filter                           | 为什么能在之前                       |
| -------------------------------- | ------------------------------------ |
| `JwtVersionFilter`               | 只校验 JWT 结构，不读 Authentication |
| `JwtBlacklistFilter`             | 你写了 `if (auth == null) 放行`      |
| `ClientIdTenantResolutionFilter` | 根本不关心 JWT                       |

👉 它们是“前置校验”
👉 TenantFilter 是“后置消费”

> ❌ Authentication 不可能在 `BearerTokenAuthenticationFilter` 之前存在
>
> ✅ 它是在这个 Filter 内部诞生的
>
> ✅ 只有 `authorizeHttpRequests()` 允许认证，它才会诞生
>
> ✅ TenantFilter 想拿 Authentication，就必须放在它后面
