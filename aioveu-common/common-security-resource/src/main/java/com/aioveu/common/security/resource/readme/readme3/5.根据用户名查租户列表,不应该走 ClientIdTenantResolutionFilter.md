## 二、为什么这个接口「不能」用 clientId 解析 tenantId？

### ❌ 你现在逻辑里的问题

你的接口是：

```text
GET /aioveu/api/v8/admin/tenant/users/tenants/{username}
```

你说得很对：

> “我还没登录，我连 tenantId 都不知道，我怎么根据 clientId 反查 tenantId？”

这在逻辑上是死循环：

```text
要知道租户列表
↓
需要先有 tenantId
↓
tenantId 要从 clientId 来
↓
但 clientId 本身就绑定 tenant
```

👉 鸡生蛋，蛋生鸡

## 三、这个接口在登录链路里的真实身份

### ✅ 它在登录链路中的位置

```text
1️⃣ 打开登录页
2️⃣ 输入用户名
3️⃣ 调用 /tenants/{username}
4️⃣ 返回该用户可登录的租户列表
5️⃣ 用户选择租户
6️⃣ /oauth/token（带上 tenantId）
```

👉 第 3 步时：
• ❌ 没有 JWT

• ❌ 没有 tenantId

• ✅ 只知道 username


✅ 所以这个接口：
• 不解析 tenantId

• 不设置 TenantContextHolder

• 不进任何租户 Filter

## 五、✅ 正确的配置方式（三步走）

---

### ✅ 1️⃣ Security 白名单（必须）

```yaml
security:
  whitelist-paths:
    - /aioveu/api/v8/admin/tenant/users/tenants/**
```

✅ 允许访问
✅ 不要求 JWT

---

### ✅ 2️⃣ `JwtAuthSkippingFilter` 明确放过

```java
@Override
protected boolean shouldNotFilter(HttpServletRequest request) {
    String uri = request.getRequestURI();

    return uri.startsWith("/aioveu/api/v8/admin/tenant/users/")
            && (
                uri.contains("/UserAuthCredentials")
             || uri.endsWith("/tenants/" + extractUsername(uri))
            );
}
```

✅ 这是“认证期 Feign / 登录前调用”
✅ 不走 JWT
✅ 不解析 tenantId

---

### ✅ 3️⃣ `ClientIdTenantResolutionFilter` **必须跳过**

```java
@Override
protected boolean shouldNotFilter(HttpServletRequest request) {
    String uri = request.getRequestURI();

    // JWT → 跳过
    String auth = request.getHeader(HttpHeaders.AUTHORIZATION);
    if (StringUtils.hasText(auth) && auth.startsWith("Bearer ")) {
        return true;
    }

    // ✅ 登录前接口 → 跳过
    if (uri.startsWith("/aioveu/api/v8/admin/tenant/users/tenants/")) {
        return true;
    }

    // 公共租户接口 → 接管
    return tenantPublicProperties.getPublicPaths().stream()
            .noneMatch(p -> new AntPathMatcher().match(p, uri));
}
```
