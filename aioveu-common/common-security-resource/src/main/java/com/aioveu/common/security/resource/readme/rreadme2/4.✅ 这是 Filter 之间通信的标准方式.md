# 二、TenantFilter 怎么接这个标识（你前面那份代码）

### ✅ 只改 `shouldNotFilter`

把你现在的：

```java
@Override
protected boolean shouldNotFilter(HttpServletRequest request) {
    return false;
}
```

改成：

```java
@Override
protected boolean shouldNotFilter(HttpServletRequest request) {
    // ✅ 公共 clientId 请求，TenantFilter 不介入
    return request.getAttribute("__PUBLIC_CLIENT_REQUEST__") != null;
}
```

✅ 不要动 `doFilterInternal`
✅ 不要判断 URL
✅ 不要判断 tenantId 是否存在

# 三、为什么这样加是「主流 + 正确」的？

### ✅ 1️⃣ 这是 Filter 之间通信的标准方式

| 方式              | 是否推荐   |
| ----------------- | ---------- |
| request attribute | ✅ 主流     |
| ThreadLocal       | ⚠️ 有坑     |
| URL 白名单        | ❌ 反模式   |
| SecurityContext   | ❌ 语义不符 |

---

### ✅ 2️⃣ 不破坏你自己的设计原则

你之前强调过：

> ❌ URL 是路由，不是语义  
> ❌ TenantFilter 永远不认 clientId  
> ❌ 资源服务器不信任前端 tenantId  

这个方案：

✅ TenantFilter 仍然不认 clientId
✅ 只是“知道这个请求归别人管”
✅ 完全由你这个 Filter 主动声明身份

---

### ✅ 3️⃣ 生命周期干净、安全

• ✅ attribute 只在当前请求有效

• ✅ 前端无法伪造

• ✅ Filter 顺序可控

• ✅ 不污染线程池
