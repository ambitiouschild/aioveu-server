## 一、一句话结论（先钉死）

> 你启动失败的根本原因不是“Filter 没进去”，而是：
>

> `ObjectProvider<OncePerRequestFilter> clientIdTenantFilterProvider`  
> ✅ 但 Spring 在 *方法参数解析阶段* 把它当成了需要注入一个 `OncePerRequestFilter` Bean

## 二、为什么之前我给你的“ObjectProvider 写法”在这里炸了

我之前说：

```java
ObjectProvider<OncePerRequestFilter> clientIdTenantFilterProvider
```

在 Spring Framework 6.x（你用的是 Spring Boot 3.x）里，这是危险写法，原因是：

• `ObjectProvider<T>` 在方法参数注入时

• Spring 会先找 `T` 类型的 Bean

• `OncePerRequestFilter` 有 8 个 → 不满足 `unique candidate`

• 即使你后面 `.getIfAvailable()`，构造期就已经失败了


👉 这正是异常里提示你去读的那个 Wiki 页的含义：

> Ensure that your compiler is configured to use the '-parameters' flag…
> Missing parameter name information

但真正的解法不是开 `-parameters`，而是：不要对“宽接口”用 ObjectProvider 做方法参数。

## 三、你现在这个架构的“唯一干净解法”（跨模块、不依赖、不冲突）

### ✅ 正确姿势：`ApplicationContext` + 按 name 拿 Bean

在 `ResourceServerConfiguration` 里：

```java
import org.springframework.context.ApplicationContext;
import org.springframework.web.filter.OncePerRequestFilter;
```

改方法签名（删掉 ObjectProvider 参数）：

```java
@Bean
@Order(0)
public SecurityFilterChain tenantResourceChain(
        HttpSecurity http,
        ApplicationContext applicationContext,   // ✅ 加这个
        JwtBlacklistFilter jwtBlacklistFilter,
        JwtVersionFilter jwtVersionFilter,
        TenantFilter tenantFilter,
        DebugFilter debugFilter,
        ResourceSecurityProperties resourceSecurityProperties
) throws Exception {
```

在方法体里这样拿：

```java
// ✅ 按名字拿，不按类型，不冲突
OncePerRequestFilter clientIdTenantFilter =
        applicationContext.getBeanProvider(OncePerRequestFilter.class)
                          .getIfAvailable(() -> null);

if (clientIdTenantFilter != null) {
    http.addFilterBefore(
        clientIdTenantFilter,
        BearerTokenAuthenticationFilter.class
    );
}
```

✅ 不 import tenant 类型  
✅ 不写 `ClientIdTenantResolutionFilter`  
✅ 不触发 8-bean 冲突  
✅ 有就装，没就跳过
