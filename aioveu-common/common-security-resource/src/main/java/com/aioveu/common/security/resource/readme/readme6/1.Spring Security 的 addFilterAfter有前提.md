# 🔴 你现在这个配置里，**真正致命的 4 个点**

------

## ❌ 致命点 1（最关键）

### **你这三个 Filter 都是 `@Component`**

```
@Slf4j
@Component
public class JwtBlacklistFilter extends OncePerRequestFilter { ... }

@Slf4j
@Component
public class JwtVersionFilter extends OncePerRequestFilter { ... }

@Slf4j
@Component
public class TenantFilter extends OncePerRequestFilter { ... }
```

### ❗ 在 Spring Boot 3 / Spring Security 6 里：

> **只要一个 Filter 是 `@Component`**
>
> ✅ Spring 会把它注册成 **Servlet 容器级 Filter**
>
> ❌ **不受 `SecurityFilterChain#addFilterAfter`控制**
>
> ❌ **执行顺序不可预测**
>
> ❌ **可能在 `BearerTokenAuthenticationFilter`之前执行**
>
> ❌ **甚至可能执行多次**

👉 **你现在日志里这个现象，就是铁证：**

```
JwtBlacklistFilter
TenantFilter
Authorization: Bearer xxx
Authentication: null
```

✅ **这说明：**

- 

  你的 Filter 已经在跑

- 

  但 `BearerTokenAuthenticationFilter`根本没出现

- 

  **不是顺序问题，是“链被污染”**

------

## ❌ 致命点 2：`addFilterAfter`对 `@Component`Filter **基本无效**

你写的是：

```
.addFilterAfter(jwtVersionFilter, BearerTokenAuthenticationFilter.class)
.addFilterAfter(jwtBlacklistFilter, BearerTokenAuthenticationFilter.class)
.addFilterAfter(tenantFilter, BearerTokenAuthenticationFilter.class)
```

### ❗ 但 Spring Security 的 `addFilterAfter`**有前提**：

> ✅ **只对「非 Servlet 容器 Filter」生效**
>
> ✅ **只对「Security 内部构建的 Filter」生效**
>
> ❌ **对 `@Component`Filter 基本无视**

官方文档原话（我给你翻译）：

> Filters registered via `FilterRegistrationBean`or detected as `@Component`
>
> are **not managed by Spring Security** and should not be added via
>
> `addFilterAfter/Before`.

👉 **你现在就是“反模式”**

# ✅✅✅ 正确的、唯一能“进 JWT”的改法（照抄）

------

## ✅ 第一步（必须）：**删掉所有 `@Component`**

### ❌ 全部删掉

```
// ❌ 删掉
@Component
public class JwtBlacklistFilter { ... }

// ❌ 删掉
@Component
public class JwtVersionFilter { ... }

// ❌ 删掉
@Component
public class TenantFilter { ... }

// ❌ 删掉
@Component
public class DebugFilter { ... }
```

✅ **一个 `@Component`都不留**

------

## ✅ 第二步：用 `@Bean`在配置类里创建 Filter

### ✅ 在 `ResourceServerConfiguration`里加：

```
@Bean
public JwtBlacklistFilter jwtBlacklistFilter(
        TokenManagerService tokenManagerService,
        SecurityProperties securityProperties
) {
    return new JwtBlacklistFilter(tokenManagerService, securityProperties);
}

@Bean
public JwtVersionFilter jwtVersionFilter(
        RedisTemplate<String, Object> redisTemplate,
        SecurityProperties securityProperties
) {
    return new JwtVersionFilter(redisTemplate, securityProperties);
}

@Bean
public TenantFilter tenantFilter() {
    return new TenantFilter();
}

@Bean
public DebugFilter debugFilter() {
    return new DebugFilter();
}
```

✅ **让 Spring Security 统一管理**

✅ **`addFilterAfter`才会真正生效**

------

## ✅ 第三步：**严格保证顺序（你现在这个顺序是对的，但要“干净”）**

```
.addFilterAfter(debugFilter, BearerTokenAuthenticationFilter.class)
.addFilterAfter(jwtVersionFilter, BearerTokenAuthenticationFilter.class)
.addFilterAfter(jwtBlacklistFilter, jwtVersionFilter.getClass())
.addFilterAfter(tenantFilter, jwtBlacklistFilter.getClass())
```

✅ **不要多个 Filter 都挂在 `BearerTokenAuthenticationFilter`上**

✅ **链式挂载最稳**

------

## ✅ 第四步：**确认 `BearerTokenAuthenticationFilter`真的存在**

启动日志里你**必须能看到类似**（哪怕不是完全一样）：

```

```


✅ **只要 JWT 没解析，这个 Filter 一定不在链里**
