## 二、为什么你现在这套“一个 aud 一个服务”在公用 jar 上行不通？

• ❌ 却只认一个 `aud`


👉 这在架构上就是矛盾的

## 三、✅ 正确改法（SaaS 公共 Resource Server 标准方案）

### ✅ 方案一（✅ 强烈推荐）：**关闭 `aud` 强制校验**

这是最标准、最干净、最不容易出事故的改法。

#### ✅ 改你的 `SecurityFilterChain`

```java
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .oauth2ResourceServer(oauth2 -> oauth2
            .jwt(jwt -> jwt
                // ✅ 只校验 issuer
                .jwtAuthenticationConverter(jwtAuthenticationConverter())
                // ✅ 不校验 audience
                .audienceValidator(aud -> OAuth2TokenValidatorResult.success())
            )
        )
        .authorizeHttpRequests(auth -> auth
            .anyRequest().authenticated()
        );

    return http.build();
}
```

✅ 这是“公共资源服务器 jar”的正确姿态

---

### ✅ 那“谁能访问谁”靠什么控制？

| 控制维度 | 用法                                            |
| -------- | ----------------------------------------------- |
| 接口级   | `@PreAuthorize("hasAuthority('TENANT_ADMIN')")` |
| 业务级   | tenant_id + role                                |
| 客户端级 | `client_id` claim                               |
| 范围级   | `scope`                                         |

#### ✅ 示例：只允许 `mall-admin` client 访问

```java
@PreAuthorize("hasAuthority('OAUTH2_CLIENT_mall-admin')")
public UserAuthCredentials getUserAuthInfo() { ... }
```

或者在 Filter 里：

```java
String clientId = jwt.getClaimAsString("client_id");
if (!"mall-admin".equals(clientId)) {
    throw new AccessDeniedException("invalid client");
}
```

## 四、✅ 方案二（进阶）：**支持多 `aud`，而不是单 `aud`**

如果你一定要保留 `aud` 语义（偏平台级 SaaS）：

```java
.audienceValidator(aud -> {
    if (aud.contains("mall-admin")
            || aud.contains("aioveu-tenant")
            || aud.contains("aioveu-common")) {
        return OAuth2TokenValidatorResult.success();
    }
    return OAuth2TokenValidatorResult.failure(
        new OAuth2Error("invalid_token", "Invalid audience", null)
    );
})
```

✅ 适合：
• 公共 jar

• 多服务共享

• 有明确“受信 aud 列表”的场景


❌ 不适合频繁新增微服务

---

## 五、✅ 方案三（最标准 OAuth2 思维）：**aud = 资源服务器角色，而不是 client**

这是很多大厂的做法：

```json
{
  "aud": "resource-server-tenant",
  "client_id": "mall-admin"
}
```

### ✅ 含义是：

| claim       | 含义                                |
| ----------- | ----------------------------------- |
| `aud`       | 这个 Token 能访问哪个资源服务器集群 |
| `client_id` | 是谁申请的 Token                    |

👉 你的公共 jar 只认：
```java
aud = "resource-server-tenant"
```

👉 不关心 client_id 是谁

✅ 这是最符合 RFC 8693 / OAuth2 语义的
✅ 但代价是：要改 Authorization Server 的 Token 签发逻辑

## 六、你这个场景的**最终推荐方案**

### ✅ 我给你一个“不后悔”的选择：

> 公共 Resource Server jar：
> - ✅ 校验 `iss`
> - ✅ 校验 `exp / nbf`
> - ❌ 不校验 `aud`
> - ✅ 用 `client_id + scope + authorities` 做访问控制

### ✅ 为什么？

| 优点                | 说明                 |
| ------------------- | -------------------- |
| ✅ 多微服务共用      | 不用为每个服务改配置 |
| ✅ 不依赖 Token 结构 | client 随便加        |
| ✅ 升级安全          | 权限在 scope / role  |
| ✅ 易维护            | 不随业务膨胀         |
