是的，**结论先给你**：

> ✅ **白名单（Spring Security 配置）改了，必须重启对应微服务。**

这不是你操作的问题，而是 **Spring Security 的设计机制决定的**。

下面我给你一个「**为什么必须重启 + 哪些不用重启**」的清晰对照表，以后就不会再纠结了。

------

## 一、为什么白名单一定要重启？

### ✅ Spring Security 的核心特点：**启动时一次性构建**

Spring Security 的 `SecurityFilterChain`是在 **应用启动时**：

- 

  只构建一次

- 

  构建完就固定

- 

  不会监听配置文件变化

也就是说：

```
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) {
    http
      .authorizeHttpRequests(auth -> auth
          .requestMatchers("/xxx").permitAll()
      );
    return http.build(); // ← 构建后就不变了
}
```

👉 **运行期间不会重新执行这个方法**

所以你哪怕：

- 

  改了 `application.yml`

- 

  改了 Nacos 配置

- 

  IDEA 里热替换了 class（部分情况也不行）

**Security 过滤器链都不会变**

------

## 二、哪些配置支持“热更新”（不用重启）

为了你以后少踩坑，我整理了一张表：

| 配置类型                      | 是否支持热更新 | 说明                   |
| ----------------------------- | -------------- | ---------------------- |
| ✅ Nacos 普通业务配置          | ✅ 支持         | `@RefreshScope`        |
| ✅ 日志级别                    | ✅ 支持         | `logging.level.*`      |
| ✅ 动态线程池                  | ✅ 支持         | dynamic-tp             |
| ✅ 业务白名单（自己维护 List） | ✅ 支持         | 自己写逻辑             |
| ❌ **Spring Security 白名单**  | ❌ 不支持       | FilterChain 启动即固化 |
| ❌ 拦截器 / 过滤器顺序         | ❌ 不支持       |                        |
| ❌ `@PreAuthorize`表达式       | ❌ 不支持       |                        |
| ❌ OAuth2 Resource Server 配置 | ❌ 不支持       |                        |

------

## 三、那有没有“不重启也能动态白名单”的办法？

有，但**不属于 Spring Security 原生能力**，而是**你自己接管逻辑**。

### ✅ 方案 1：白名单放数据库 / Redis / Nacos（推荐）

**Security 仍然拦截，但你动态决定是否放行**

```
.requestMatchers("/**").access((authentication, context) -> {
    String uri = context.getRequest().getRequestURI();
    boolean allow = whiteListService.contains(uri);
    return allow ?
        new AuthorizationDecision(true) :
        new AuthorizationDecision(false);
})
```

配合：

```
@RefreshScope
@Component
public class WhiteListService {
    @Value("#{'${security.white-list}'.split(',')}")
    private Set<String> whiteList;
}
```

✅ 支持热更新

❌ 稍微复杂一点

------

### ✅ 方案 2：自定义过滤器（最灵活）

```
@Component
public class DynamicWhiteListFilter extends OncePerRequestFilter {

    @Value("#{'${security.white-list}'.split(',')}")
    private Set<String> whiteList;

    @Override
    protected boolean shouldNotFilter(HttpServletRequest request) {
        return whiteList.stream().anyMatch(request.getRequestURI()::startsWith);
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                   HttpServletResponse response,
                                   FilterChain filterChain) {
        filterChain.doFilter(request, response);
    }
}
```

⚠️ 要注意顺序：

```
.addFilterBefore(dynamicWhiteListFilter, BasicAuthenticationFilter.class)
```

------

### ✅ 方案 3：Nacos + 手动刷新 Security（高级玩法，不推荐）

通过反射 + 重建 `FilterChainProxy`

👉 **生产环境不建议**，容易出诡异问题。
