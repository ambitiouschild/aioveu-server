## 二、为什么“没有 clientId”这一点非常关键？

### 1️⃣ `ClientIdTenantResolutionFilter` 的存在前提就是：

> ✅ 有 clientId
> ✅ 能解析出 tenantId
> ✅ 能自证身份

你这个 Feign 调用：

| 条件            | 是否满足                        |
| --------------- | ------------------------------- |
| 有 clientId     | ❌ 没有                          |
| 能解析 tenantId | ❌ 不能                          |
| 需要租户解析    | ❌ 不需要（tenantId 已经是参数） |

👉 它连“进这个 Filter 的门票”都没有

---

### 2️⃣ 那它现在在干嘛？

它只是在做一件事：

```text
用已有的 tenantId + username
→ 查用户凭证
```

✅ 不解析租户
✅ 不判断租户合法性
✅ 不依赖租户上下文做任何业务决策

👉 TenantFilter 对它来说，是“多余的一道强制 JWT 关卡”

## 三、所以你现在这个接口，本质是什么？

• ❌ 公共接口

• ❌ 业务接口

• ❌ 资源接口

• ❌ 租户解析接口

## 四、那正确的处理方式只有一个（你其实已经想到了）

```java

protected boolean shouldNotFilter(HttpServletRequest request) {
    String uri = request.getRequestURI();

    // ✅ 认证服务内部调用，无 JWT，仅用于加载用户凭证
    return uri.startsWith("/aioveu/api/v8/admin/tenant/users/")

```

### ✅ 再加一句“定案级注释”

```java
/**
```
