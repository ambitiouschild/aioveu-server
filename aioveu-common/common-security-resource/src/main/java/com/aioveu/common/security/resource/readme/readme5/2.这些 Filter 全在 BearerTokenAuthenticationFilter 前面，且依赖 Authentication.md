## 三、那为什么我“现在”才把顺序钉死？

因为顺序问题，只有在你确认了下面三点之后，才有资格被钉死：

1️⃣ Authentication 只能来自 BearerTokenAuthenticationFilter  
2️⃣ 它只在请求被认定为 authenticated() 时才创建  
3️⃣ 你的 Filter 在消费 Authentication，而不是创建它

这三点全部确认后，顺序才从“嫌疑”变成“铁案”。

否则，我如果第一轮就只说：

> “你顺序反了”

你完全可以反问一句：

> “那为什么 JwtVersionFilter 不读 Authentication 也能放 before？”

——你刚才那句反问，本身就是正确的质疑。

## 四、现在这套顺序，是最终答案吗？

✅ 是

对你这套架构来说，最终正确顺序只有这一条：

```java
.addFilterBefore(clientIdTenantResolutionFilter, BearerTokenAuthenticationFilter.class)

.addFilterAfter(jwtVersionFilter, BearerTokenAuthenticationFilter.class)
.addFilterAfter(jwtBlacklistFilter, BearerTokenAuthenticationFilter.class)
.addFilterAfter(tenantFilter, BearerTokenAuthenticationFilter.class)
```

不再摇摆，不再讨论，不再例外。
