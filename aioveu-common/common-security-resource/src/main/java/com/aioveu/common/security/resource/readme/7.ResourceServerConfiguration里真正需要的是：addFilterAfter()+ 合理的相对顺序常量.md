## 二、为什么你这个配置里「不需要 Order 注解 / Ordered 实现」？

### ✅ 关键点：你用的是 `SecurityFilterChain`

```java
.addFilterBefore(jwtVersionFilter, BearerTokenAuthenticationFilter.class)
.addFilterBefore(jwtBlacklistFilter, BearerTokenAuthenticationFilter.class)
.addFilterBefore(tenantFilter, BearerTokenAuthenticationFilter.class)
```

👉 Spring Security 会严格按照你声明的“相对顺序”插入 Filter

### ✅ 此时：

| 决定顺序的因素            | 是否生效   |
| ------------------------- | ---------- |
| `Ordered` 接口            | ❌ 不生效   |
| `@Order` 注解             | ❌ 不生效   |
| `addFilterBefore / After` | ✅ 唯一生效 |
| Filter 注册顺序           | ❌ 不生效   |

👉 你之前那个 `SecurityFilterOrders` 在这套写法下，完全是“摆设”

## 四、正确的顺序应该是（资源服务器标准版 ✅）

### ✅✅✅ 正确顺序（强烈推荐）

```java
// 1️⃣ JWT 先解码
// 2️⃣ 再校验版本
// 3️⃣ 再校验黑名单
// 4️⃣ 最后解析租户
http
    .addFilterAfter(jwtVersionFilter, BearerTokenAuthenticationFilter.class)
    .addFilterAfter(jwtBlacklistFilter, BearerTokenAuthenticationFilter.class)
    .addFilterAfter(tenantFilter, BearerTokenAuthenticationFilter.class)
```

### ✅ 执行顺序变成：

```
BearerTokenAuthenticationFilter
→ JwtDecoder.decode()
→ JwtAuthenticationConverter
→ jwtVersionFilter ✅
→ jwtBlacklistFilter ✅
→ tenantFilter ✅
→ Controller
→ MP 租户插件
```

👉 JWT 已存在、Authentication 已存在、tenantId 可取

## 五、那 `SecurityFilterOrders` 还要不要？

### ✅ 要，但要**降级使用**

它只应该表达 “相对语义”，而不是“绝对位置”

### ✅ 推荐改法（语义化）

```java
public final class SecurityFilterOrders {

    /** ✅ 公共租户解析（不依赖 JWT） */
    public static final int PUBLIC_TENANT_FILTER = Ordered.HIGHEST_PRECEDENCE + 10;

    /** ✅ JWT 已解码之后 */
    public static final int JWT_VERSION_FILTER = 100;

    /** ✅ 可安全访问 JwtAuthenticationToken */
    public static final int JWT_BLACKLIST_FILTER = 200;

    /** ✅ 从 JWT 取 tenantId */
    public static final int TENANT_FILTER = 300;

    private SecurityFilterOrders() {}
}
```

### ✅ 然后 Filter 自己实现 `Ordered`

```java
public class JwtVersionFilter extends OncePerRequestFilter implements Ordered {

    @Override
    public int getOrder() {
        return SecurityFilterOrders.JWT_VERSION_FILTER;
    }
}
```

### ⚠️ 但注意：

> **在 `SecurityFilterChain` 中用 `addFilterAfter()` 时，  
> `Ordered` 会被 Spring Security 覆盖**

👉 所以它只是“可读性保障”，不是“控制力”

## 六、你这个配置里，**唯一需要“顺序”的地方是哪里？**

### ✅ 只有这一个地方需要认真设计顺序：

```java
SecurityFilterChain
  └── addFilterAfter(...)
```

### ❌ 其他地方都不需要：

• ❌ Filter 类上的 `@Order`

• ❌ `Ordered` 接口（除非你用 `FilterRegistrationBean`）

• ❌ `HIGHEST_PRECEDENCE + N`
