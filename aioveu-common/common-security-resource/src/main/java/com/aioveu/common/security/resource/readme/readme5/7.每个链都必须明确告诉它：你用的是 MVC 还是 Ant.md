## 三、为什么之前没事，现在一拆链就炸？

因为你刚刚做了这件事 ✅（你前面自己说的）：

> ✅ 拆了两条 SecurityFilterChain

一旦你有了 多个 FilterChain：

```java

@Bean
@Order(2)
```

Spring Security 6.x 会强制要求：

> 每个链都必须明确告诉它：你用的是 MVC 还是 Ant

这是 Spring Security 6.x 的“保护机制”，不是 bug。

## 五、✅ 正确、稳定、生产级修法（你直接照抄）

### ✅ 方案一（最推荐）：**全部改用 `AntPathRequestMatcher`（最稳）**

你这个服务是 纯 REST API + 网关转发，根本不需要 MVC 的高级匹配能力。

#### ✅ tenantPublicChain（公共接口链）

```java
@Bean
@Order(1)
public SecurityFilterChain tenantPublicChain(HttpSecurity http) throws Exception {
    http
        .securityMatcher(
            AntPathRequestMatcher.antMatcher("/aioveu/api/v8/admin/tenant/users/tenants/**"),
            AntPathRequestMatcher.antMatcher("/aioveu/api/v8/admin/tenant/users/**/authInfo"),
            AntPathRequestMatcher.antMatcher("/aioveu/api/v8/admin/tenant/users/**/UserAuthCredentials")
        )
        .authorizeHttpRequests(auth -> auth.anyRequest().permitAll())
        .csrf(AbstractHttpConfigurer::disable);
    return http.build();
}
```

#### ✅ tenantResourceChain（JWT 接口链）

```java
@Bean
@Order(2)
public SecurityFilterChain tenantResourceChain(
        HttpSecurity http,
        HandlerMappingIntrospector introspector
) throws Exception {

    MvcRequestMatcher.Builder mvc = new MvcRequestMatcher.Builder(introspector);

    http
        .securityMatcher(
            AntPathRequestMatcher.antMatcher("/aioveu/api/v8/admin/tenant/**")
        )
        .authorizeHttpRequests(auth -> auth
            .requestMatchers(
                AntPathRequestMatcher.antMatcher("/aioveu/api/v8/admin/tenant/users/me")
            ).authenticated()
            .anyRequest().authenticated()
        )
        .oauth2ResourceServer(oauth2 -> oauth2.jwt())
        .addFilterAfter(jwtVersionFilter, BearerTokenAuthenticationFilter.class)
        .addFilterAfter(jwtBlacklistFilter, BearerTokenAuthenticationFilter.class)
        .addFilterAfter(tenantFilter, BearerTokenAuthenticationFilter.class)
        .csrf(AbstractHttpConfigurer::disable);

    return http.build();
}
```

✅ `securityMatcher` 用 Ant
✅ 内部 `requestMatchers` 也用 Ant
✅ Spring Security 6.x 不再纠结
✅ 不会再出现这个异常

## 七、为什么我强烈建议你用 Ant 而不是 Mvc？

| 对比项         | AntPathMatcher | MvcRequestMatcher |
| -------------- | -------------- | ----------------- |
| 适合 REST API  | ✅ 非常适合     | ❌ 过度设计        |
| 网关转发       | ✅ 稳定         | ❌ 容易踩坑        |
| 多 FilterChain | ✅ 友好         | ❌ 容易炸          |
| 路径变量       | ❌ 不支持       | ✅ 支持            |
| 你需要吗       | ❌ 不需要       | ❌ 不需要          |

👉 你这套架构：网关 + REST + JWT
👉 Ant 是唯一正确选择
