这些类**全部来自 MyBatis‑Plus 和 JSqlParser**，它们**不属于 Spring Security，也不属于你的 security-resource 模块原本该引的东西**。

现在爆红的唯一原因是：

> **`common-security-resource`的 `pom.xml`里，没有显式声明这些依赖**

我来给你一个**“直接能抄”的依赖清单 + 正确做法**。

------

## ✅ 一、这些 import 分别属于谁

| import                                                       | 所属依赖                 |
| ------------------------------------------------------------ | ------------------------ |
| `com.baomidou.mybatisplus.core.toolkit.ObjectUtils`          | `mybatis-plus-core`      |
| `com.baomidou.mybatisplus.core.toolkit.StringPool`           | `mybatis-plus-core`      |
| `com.baomidou.mybatisplus.extension.plugins.handler.DataPermissionHandler` | `mybatis-plus-extension` |
| `net.sf.jsqlparser.*`                                        | `jsqlparser`             |

👉 **MyBatis‑Plus 会自动带 JSqlParser**

------

## ✅ 二、在 `common-security-resource/pom.xml`里加这些（最小集）

```
<!-- MyBatis-Plus 核心（ObjectUtils / StringPool） -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-core</artifactId>
</dependency>

<!-- MyBatis-Plus 扩展（DataPermissionHandler） -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-extension</artifactId>
</dependency>

<!-- JSqlParser（SQL 解析） -->
<dependency>
    <groupId>com.github.jsqlparser</groupId>
    <artifactId>jsqlparser</artifactId>
</dependency>
```

✅ **不需要写版本号**（Boot / 父 POM 管）

✅ **`mybatis-plus-boot-starter`其实已经间接带了前三个，但 resource 模块不建议引 starter**

------

## ✅ 三、但——「架构上更正确的做法」是这样的

你前面我们已经定过规矩：

> **`common-security-resource`不应该依赖 MyBatis**

所以**更优雅的解法**是：

### ✅ 方案 A（推荐 ✅）：只留“接口依赖”，实现延迟绑定

#### 1️⃣ `common-security-resource`只留：

```
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-extension</artifactId>
</dependency>
<dependency>
    <groupId>com.github.jsqlparser</groupId>
    <artifactId>jsqlparser</artifactId>
</dependency>
```

- 

  `DataPermissionHandler`是**接口**

- 

  `JSqlParser`是**SQL 表达式工具**

- 

  这两者**可以接受在 resource 里**

- 

  `ObjectUtils / StringPool`**其实可以去掉**（下面说）

------

### ✅ 方案 B（更纯 ✅✅）：删掉 MP core 的依赖

你代码里：

```
ObjectUtils.isNotEmpty(annotation)
StringPool.DOT
```

这俩**不是必须**，可以改成 JDK：

```
annotation != null
'.'
```

改完后：

✅ 不再需要 `mybatis-plus-core`

✅ resource 模块只依赖：

- 

  `mybatis-plus-extension`

- 

  `jsqlparser`

- 

  `common-security-core`

👉 **这是最干净的企业级形态**

------

## ✅ 四、我帮你“去 MP-core 化”后的最小改动


✅ 编译过

✅ 语义完全一样

✅ 依赖更少

## ✅ 五、最终推荐 `common-security-resource/pom.xml`片段

- 

  `mybatis-plus-boot-starter`

- 

  `mybatis-spring-boot-starter`

- 

  `mybatis-plus-core`（能不引就不引）
