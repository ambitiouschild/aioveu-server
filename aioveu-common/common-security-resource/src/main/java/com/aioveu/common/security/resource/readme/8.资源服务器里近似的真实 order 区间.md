## 四、`Ordered`的顺序值到底代表什么？

### ✅ 先看源码定义

```
public interface Ordered {

    int HIGHEST_PRECEDENCE = Integer.MIN_VALUE; // -2147483648
    int LOWEST_PRECEDENCE  = Integer.MAX_VALUE; //  2147483647

```

### ✅ 记住一句话（非常重要）

> **数字越小 → 越早执行
>
> 数字越大 → 越晚执行**

## 六、那为什么你“顺序值很小，却还是错”？

### ❌ 因为你混淆了两件事：

| 概念       | 你以为   | 实际 |
| ---------- | -------- | ---- |
| 顺序值小   | 更早     | ✅    |
| 更早       | 更好     | ❌    |
| JWT Filter | 越早越好 | ❌    |

👉 **JWT 相关 Filter 的“正确顺序值”不是“更小”，而是“在 JWT 解码之后”**

## 七、正确的“顺序值语义模型”（你以后该用的）


👉 **顺序值 = 可读性**

👉 **addFilterAfter = 控制权**
