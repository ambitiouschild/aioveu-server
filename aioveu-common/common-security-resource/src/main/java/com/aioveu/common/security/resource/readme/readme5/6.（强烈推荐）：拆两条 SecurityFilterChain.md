## 三、那问题出在哪？（致命点在这里）

### ❌ 问题不在白名单内容
### ❌ 问题在 **你使用它的方式**

你之前贴的 `ResourceServerConfiguration` 里是这么用的：

```java
for (String whitelistPath : securityProperties.getWhitelistPaths()) {
    requests.requestMatchers(
        AntPathRequestMatcher.antMatcher(whitelistPath)
    ).permitAll();
}
requests.anyRequest().authenticated();
```

### ✅ 在 Spring Security 眼里，这等价于：

```java
.requestMatchers("/aioveu/api/v8/admin/tenant/**").permitAll();
```

为什么？

因为：

```text
/users/{username}/authInfo
/users/{username}/UserAuthCredentials
/users/{username}/{tenantId}/UserAuthCredentials
/users/tenants/{username}
```

👉 全部落在同一个父路径下
👉 AntPathMatcher 先命中
👉 `permitAll()` 先生效
👉 `/users/me` 被“顺带放过”

## 六、✅ tenant 微服务白名单的「正确打开方式」（重点）

### ✅ 方案一（强烈推荐）：**拆两条 SecurityFilterChain**

```java
// ✅ 链 1：tenant 公共接口（不走 JWT）
@Bean
@Order(1)
public SecurityFilterChain tenantPublicChain(HttpSecurity http) throws Exception {
    http
        .securityMatcher(
            "/aioveu/api/v8/admin/tenant/users/tenants/**",
            "/aioveu/api/v8/admin/tenant/users/**/authInfo",
            "/aioveu/api/v8/admin/tenant/users/**/UserAuthCredentials"
        )
        .authorizeHttpRequests(auth -> auth.anyRequest().permitAll())
        .csrf().disable();
    return http.build();
}

// ✅ 链 2：tenant JWT 接口（必须认证）
@Bean
@Order(2)
public SecurityFilterChain tenantResourceChain(HttpSecurity http) throws Exception {
    http
        .securityMatcher("/aioveu/api/v8/admin/tenant/**")
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/aioveu/api/v8/admin/tenant/users/me")
                .authenticated()
            .anyRequest().authenticated()
        )
        .oauth2ResourceServer(oauth2 -> oauth2.jwt())
        .addFilterAfter(jwtVersionFilter, BearerTokenAuthenticationFilter.class)
        .addFilterAfter(jwtBlacklistFilter, BearerTokenAuthenticationFilter.class)
        .addFilterAfter(tenantFilter, BearerTokenAuthenticationFilter.class);
    return http.build();
}
```

✅ 公共接口链：永远不碰 JWT
✅ JWT 链：永远不处理公共接口
✅ 彻底解耦，永不覆盖
