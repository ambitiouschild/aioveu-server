## 二、你这个 `getTenantId()` 到底做了什么？（非常关键）

### ✅ 你的实现（正确版）

```java
public static Long getTenantId() {
    // 1️⃣ JWT 中优先
    Jwt jwt = getJwt();
    if (jwt != null) {
        Object tenantId = jwt.getClaim(JwtClaimConstants.Tenant.ID);
        if (tenantId != null) {
            return Long.valueOf(tenantId.toString());
        }
    }

    // 2️⃣ 公共接口 / 系统态
    return TenantContextHolder.getTenantId();
}
```

### ✅ `getJwt()` 的实现（也非常正确）

```java
private static Jwt getJwt() {
    Authentication authentication = getAuthentication();
    if (authentication instanceof JwtAuthenticationToken jwtAuth) {
        return jwtAuth.getToken();
    }
    return null;
}
```

👉 逻辑是完美的
👉 Controller / Service 里能拿到 3，说明 JWT 确实有 tenant_id

---

## 三、那为什么 `TenantFilter` 里会是 `null`？（真因）

### ✅ 从你前面的日志里，有一个“决定性证据”：

```text
TenantFilter → SecurityUtils.getTenantId() = null
UserServiceImpl → SecurityUtils.getTenantId() = 3
```

### ✅ 这说明什么？

说明在 `TenantFilter` 执行时：

```java
SecurityContextHolder.getContext().getAuthentication()
```

还不是 `JwtAuthenticationToken`

可能处于以下状态之一：

| 状态                           | 说明                     |
| ------------------------------ | ------------------------ |
| `null`                         | SecurityContext 还没写入 |
| `AnonymousAuthenticationToken` | 匿名占位                 |
| `OAuth2AuthenticationToken`    | 非 JWT                   |
| 被装饰过的 Authentication      | Observation / AOP 包装   |

👉 而你的 `getJwt()` 只认 `JwtAuthenticationToken`

---

## 四、为什么 Controller 里又可以？

因为执行顺序是：

```text
BearerTokenAuthenticationFilter
→ JwtDecoder
→ 创建 JwtAuthenticationToken
→ SecurityContextHolder.setAuthentication(...)
→ Filter链继续执行
→ Controller
```

### ✅ Controller 在 **Filter 链完全结束后**
### ❌ TenantFilter 在 **链中间**

即使你写了：

```java
.addFilterAfter(tenantFilter, BearerTokenAuthenticationFilter.class)
```

在 Spring Security 6 + Observation + WebMvcSecurityConfiguration 环境下：

• `SecurityContext` 可能被延迟写入

• `ObservationFilterChainDecorator` 会包装

• `SecurityContextPersistenceFilter` 行为变化


👉 在 Filter 中，`instanceof JwtAuthenticationToken` 不是 100% 稳定的

## 五、那你现在这个 `JwtSecurityUtils` 要不要改？

### ✅✅✅ 结论：**不要改它**

原因有三个：

1️⃣ 它在 Controller / Service 层 100% 正确  
2️⃣ 它是“业务工具类”，不是“基础设施引导类”  
3️⃣ 你如果为了 Filter 改它，会污染整个设计

👉 `JwtSecurityUtils` 的定位是：
> ✅ 业务代码用  
> ❌ Filter / Interceptor 里不该是主要依赖

## 六、那 `TenantFilter` 该怎么写？（这才是正解）

### ✅✅✅ **TenantFilter 不应该调用 `JwtSecurityUtils.getTenantId()`**

### ✅ 正确做法：`TenantFilter` 自己读 `JwtAuthenticationToken`

```java
@Override
protected void doFilterInternal(
        HttpServletRequest request,
        HttpServletResponse response,
        FilterChain filterChain
) throws ServletException, IOException {

    Authentication authentication =
            SecurityContextHolder.getContext().getAuthentication();

    if (authentication instanceof JwtAuthenticationToken jwtAuth) {

        Jwt jwt = jwtAuth.getToken();
        Object tenantIdObj = jwt.getClaim("tenant_id");

        if (tenantIdObj instanceof Number n) {
            long tenantId = n.longValue();
            TenantContextHolder.setTenantId(tenantId);
            log.info("【TenantFilter】从 JWT 设置租户ID: {}", tenantId);
        } else {
            throw new IllegalStateException(
                    "JWT 缺失 tenant_id，URI=" + request.getRequestURI()
            );
        }
    } else {
        // 匿名请求不应进入 /me
        throw new IllegalStateException(
                "非 JWT 认证请求，URI=" + request.getRequestURI()
        );
    }

    try {
        filterChain.doFilter(request, response);
    } finally {
        // 由 Interceptor 清理
    }
}
```

✅ 这是 Spring Security 官方推荐姿势
✅ 100% 不依赖工具类
✅ 不依赖线程安全假设
