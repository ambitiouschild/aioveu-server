## 一、为什么会出现这个报错（先懂原因）

> `interceptorIgnore` 不是 MyBatis 原生的 XML 属性

它是 MyBatis-Plus 的扩展属性，只能用在：

✅ MP 自己的 XML 解析链里
❌ 不能直接写在原生 `<select>` 上（IDEA / MyBatis DTD 会红，但运行时可能也不认）

你现在的报错：

```
Attribute interceptorIgnore is not allowed here
```

说明两件事之一：

1. IDEA 按 MyBatis DTD 校验 → 不认识这个属性（最常见）
2. 或者你用的 MP 版本 / 解析方式，没走到 MP 的 `MybatisMapperStatementConverter`

---

## 二、✅ 正确、官方、100% 生效的写法（推荐）

### ✅ 方案 1：Mapper 接口注解（最稳、最干净）

不要写在 XML 里，写在 Mapper 接口上：

```java
@Mapper
@InterceptorIgnore(tenantLine = "true")
public interface DatabaseMapper {

    List<TablePageVO> getTablePage(@Param("queryParams") QueryParams params);

    TableMetaData getTableMetadata(@Param("tableName") String tableName);

    List<ColumnMetaData> getTableColumns(@Param("tableName") String tableName);
}
```

✅ 这是 MP 官方主推方式  
✅ 不受 XML DTD 限制  
✅ 分页 COUNT 也生效  

---

### ✅ 方案 2：XML 里用 MP 的 `mybatis-plus` 命名空间（如果你坚持 XML）

把 mapper 头改成：

```xml
<mapper namespace="com.aioveu.tenant.aioveu11Codegen.mapper.DatabaseMapper"
        xmlns:mp="http://mybatis.plus/schema">
```

然后写：

```xml
<select id="getTablePage"
        resultType="..."
        mp:interceptorIgnore="tenantLine=true"
        databaseId="mysql">
```

⚠️ 但说实话：不如直接用注解，少踩坑。

## 三、你现在这个 XML 的正确“回退版”（立刻止血）

先把 XML 还原成不带 `interceptorIgnore` 属性的版本：

```xml
<select id="getTablePage"
        resultType="com.aioveu.tenant.aioveu11Codegen.model.vo.TablePageVO"
        databaseId="mysql">
```

然后去 Mapper 接口加：

```java
@InterceptorIgnore(tenantLine = "true")
List<TablePageVO> getTablePage(@Param("queryParams") Object queryParams);
```

另外两个也一起加：

```java
@InterceptorIgnore(tenantLine = "true")
TableMetaData getTableMetadata(@Param("tableName") String tableName);

@InterceptorIgnore(tenantLine = "true")
List<ColumnMetaData> getTableColumns(@Param("tableName") String tableName);
```

## 四、为什么之前我让你写 XML 属性？（解释一下）

我前面说“在 XML 里加”是基于 MP 文档的语义级正确，但：

• IDEA DTD 一定会红

• 很多项目实际只认 注解方式

• 分页 COUNT 场景，注解比 XML 更可靠


所以现在纠正为：

> ✅ codegen / 系统表 → 用 `@InterceptorIgnore(tenantLine = "true")`  
> ✅ XML 只写纯 SQL
