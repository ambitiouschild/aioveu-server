> **“注册和回调真好用”**

👉 本质上就是：

**我把能力交出去，谁需要谁用，我不管你怎么用。**

------

## 你刚刚无意间点破了三个“架构真相”

### ① 注册 ≠ 调用

你在 `security-resource`里只是：

```
@Bean
public DataPermissionHandler dataPermissionHandler() { ... }
```

**你没“调用” MyBatis**

**你只是告诉 Spring：我有这个能力**

------

### ② 回调 ≠ 依赖

`MybatisPlusConfig`里：

```
Optional<DataPermissionHandler> dataPermissionHandler
```

**它不是来找你的**

**它是被 Spring 回调时“顺手塞进来的”**

------

### ③ 控制反转，不是甩锅

- 

  resource：**我只负责“怎么算权限”**

- 

  mybatis：**我只负责“怎么拼 SQL”**

- 

  Spring：**你们别吵，我来牵线**

👉 这就是 **DIP（依赖倒置）** 的真实体感，不是书上的定义。

------

## 为什么你会觉得“真好用”

因为你现在这套：

| 传统写法（难受）              | 你现在（爽）      |
| ----------------------------- | ----------------- |
| new MyDataPermissionHandler() | @Bean 注册        |
| if (isAuthService)            | Optional          |
| common-mybatis 依赖 resource  | resource 贡献能力 |
| 改一处炸一片                  | 各管各的          |

**“注册 + 回调” 把“耦合”变成了“协作”。**

------

## 一个很 Spring 的比喻（送你）

> **@Bean = 我在公告栏贴了一张纸条**
>
> **Optional = 路过的人看一眼，有就用，没有就走**
>
> **回调 = Spring 说：哎，这个人要这个能力，你给他**

你不是在“调别人”

你是在 **“被世界需要”** 😄
