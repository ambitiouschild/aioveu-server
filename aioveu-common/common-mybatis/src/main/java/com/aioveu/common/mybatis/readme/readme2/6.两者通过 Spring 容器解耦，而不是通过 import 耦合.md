你现在这个局面，是标准 SPI 场景，不是设计错误。

## ✅ 一句话结论（先拍板）

> ✅ `MyDataPermissionHandler` 放在 `security-resource` 是完全正确的
>
> ✅ `common-mybatis` 只能“声明需要”，不能“知道实现”
>
> ✅ 通过 `Optional<DataPermissionHandler>` + `@ConditionalOnBean` 解耦
>
> ❌ 绝对不能在 `common-mybatis` 里 `new MyDataPermissionHandler()`

## 二、为什么现在“不能直接用”

你现在如果这样写：

```java
new DataPermissionInterceptor(new MyDataPermissionHandler());
```

等价于：

```
common-mybatis
  ↓ 编译期依赖
security-resource
```

👉 DAO 层 → 应用层
👉 循环依赖闭环
👉 auth / gateway / pms 都被迫依赖 security-resource

---

## 三、✅ 正确的“三层分工”（这是核心）

| 模块                   | 职责                                            |
| ---------------------- | ----------------------------------------------- |
| `common-security-core` | 定义 SPI 语义（`@DataPermission`）              |
| `common-mybatis`       | 声明：“我需要一个 `DataPermissionHandler` Bean” |
| `security-resource`    | 提供：`MyDataPermissionHandler` 实现            |

---

## 四、✅ 正确实现步骤（一步一步）

---

### ✅ Step 1：`security-resource` 暴露 Bean（唯一实现点）

📍 `common-security-resource/config/ResourceSecurityConfig.java`

```java
@Configuration
@ConditionalOnClass(DataPermissionHandler.class)
public class ResourceSecurityConfig {

    /**
     * 数据权限处理器（资源服务器提供）
     */
    @Bean
    @Primary
    @ConditionalOnMissingBean(DataPermissionHandler.class)
    public DataPermissionHandler dataPermissionHandler() {
        return new MyDataPermissionHandler();
    }
}
```

✅ 只在 resource 服务存在
✅ auth / gateway / pms 不会有这个 Bean
✅ 完全可控

---

### ✅ Step 2：`common-mybatis` 只“声明需要”（不关心实现）

📍 `MybatisPlusConfig.java`

```java
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor(
        Optional<TenantLineHandler> tenantLineHandler,
        Optional<DataPermissionHandler> dataPermissionHandler
) {

    MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

    // 1️⃣ 乐观锁
    interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());

    // 2️⃣ 多租户
    if (mybatisProperties.isTenantEnabled() && tenantLineHandler.isPresent()) {
        interceptor.addInnerInterceptor(
            new TenantLineInnerInterceptor(tenantLineHandler.get())
        );
    }

    // 3️⃣ 数据权限（✅ 关键）
    if (mybatisProperties.isDataPermissionEnabled()
            && dataPermissionHandler.isPresent()) {
        interceptor.addInnerInterceptor(
            new DataPermissionInterceptor(dataPermissionHandler.get())
        );
    }

    // 4️⃣ 分页
    interceptor.addInnerInterceptor(
        new PaginationInnerInterceptor(resolveDbType())
    );

    return interceptor;
}
```

✅ MyBatis 不知道 `MyDataPermissionHandler` 是谁
✅ 只关心 Spring 容器里有没有 Bean
✅ 没有依赖 security-resource

---

### ✅ Step 3：YAML 控制是否启用（部署决策）

#### ✅ PMS / SMS（需要数据权限）

```yaml
mybatis:
  tenant-enabled: true
  data-permission-enabled: true
```

#### ✅ auth 服务（不需要）

```yaml
mybatis:
  tenant-enabled: false
  data-permission-enabled: false
```

✅ auth 服务启动时：
• `DataPermissionHandler` Bean 存在

• 但 `data-permission-enabled=false`

• 插件不会加载

## 六、❌ 为什么不能 `@Autowired MyDataPermissionHandler`

```java
@Autowired
private MyDataPermissionHandler dataPermissionHandler; // ❌
```

原因：

| 问题         | 说明                                      |
| ------------ | ----------------------------------------- |
| 编译期强依赖 | common-mybatis 必须依赖 security-resource |
| 无法缺失     | auth 服务必须引入 resource                |
| 违背 SPI     | 基础设施依赖应用实现                      |

👉 `Optional<T>` 是唯一正确姿势
