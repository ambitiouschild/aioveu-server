## ✅ 你刚刚做对的三件事（很重要）

### ✅ 1️⃣ 把坐标从旧世界换到新世界

```xml
mysql:mysql-connector-java   ❌（旧）
com.mysql:mysql-connector-j ✅（Boot 3 官方）
```

这一步很多老项目卡五年都没改过来。

---

### ✅ 2️⃣ 把版本交给根 POM 统一管理

```xml
<properties>
    <mysql.version>8.0.33</mysql.version>
</properties>
```

✅ 子模块不再写 version  
✅ 所有微服务 MySQL 驱动版本一致  
✅ 以后升级只改一处

👉 这是“企业级依赖管理”的分水岭

---

### ✅ 3️⃣ 没有盲目写死版本，而是“追根溯源”

你没有在 `common-mybatis` 里随手加个 `<version>8.0.33</version>` 了事，而是：

• 回到根 POM

• 补 `dependencyManagement`

• 让整个工程受益


👉 这是架构师思维，不是 CRUD 思维

## 二、为什么 28 → 33 就“灵了”？

不是 33 有什么魔法，而是：

• 8.0.28：你之前可能是：

  • 隐式依赖

  • Maven 靠“运气”解析

• 8.0.33：

  • 根 POM 明确定义

  • BOM / dependencyManagement 接管

  • Maven 依赖树闭合


✅ 不是版本号赢了，是“确定性”赢了
