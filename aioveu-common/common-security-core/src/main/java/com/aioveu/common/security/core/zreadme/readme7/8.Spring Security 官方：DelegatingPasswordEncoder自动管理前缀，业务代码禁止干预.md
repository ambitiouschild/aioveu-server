✅ 一句话终极答案：

> **不是你必须加前缀，而是：  
> 👉 如果用 `DelegatingPasswordEncoder` —— 前缀它自动加，你千万别动；  
> 👉 如果用 `BCryptPasswordEncoder` —— 根本就没有前缀，你也别加。**

结论：你永远、永远、永远不需要手动加前缀。

## 一、把这件事彻底讲死（两种场景）

### ✅ 场景 1：你用的是 `DelegatingPasswordEncoder`（✅ 推荐）

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return PasswordEncoderFactories.createDelegatingPasswordEncoder();
}
```

#### 数据库里长这样（✅ 正确）：
```
{bcrypt}$2a$10$xxxxxxxx
```

#### 你的代码应该这样（✅ 正确）：
```java
passwordEncoder.encode("123456");
```

#### ❌ 你不应该这样做：
```java
"{bcrypt}" + passwordEncoder.encode(...)
```

👉 前缀是 Spring 加的，不是你加的

---

### ✅ 场景 2：你用的是 `BCryptPasswordEncoder`

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

#### 数据库里长这样（✅ 正确）：
```
$2a$10$xxxxxxxx
```

#### ❌ 没有 `{bcrypt}`，你也别加

## 二、为什么网上有人“加了前缀”？

那是 误解 / 旧代码 / 自己造轮子。

| 来源                   | 真相                                   |
| ---------------------- | -------------------------------------- |
| 老博客                 | Spring Security 4 时代                 |
| 自己写 PasswordEncoder | 自维护前缀                             |
| 看源码没看全           | 只看到存储格式，没看到 encode() 已包含 |

官方态度：

> ❌ 业务代码不应感知前缀  
> ✅ 前缀是 `PasswordEncoder` 的内部协议
