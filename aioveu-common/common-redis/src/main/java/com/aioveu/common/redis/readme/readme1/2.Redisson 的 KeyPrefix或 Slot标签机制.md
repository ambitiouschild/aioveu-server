好问题！这个 `{}` 不是你代码里写的，也不是你拼错的。

它是 Redisson 自动给你加的。

---

## 🎯 为什么会有 `{}`？

### 答案：**Redisson 的 `KeyPrefix` 或 `Slot` 标签机制**

Redisson 有一个特性叫 `{ }` 哈希标签（Hash Tag），本来是为 Redis Cluster 模式 设计的：

> Redis Cluster 要求同一个业务相关的 key 落到同一个 slot（分片）上，就用 `{ }` 包住公共部分来算 slot。

但 Redisson 在 单机模式 下也会"顺手"给你加上 `{}`，原因有两个可能：

---

### 可能 ①：你（或 common 模块）配了 `keyPrefix`

Redisson 配置里如果有：

```yaml
redisson:
  config:
    keyPrefix: "{aioveu}"   # 或者类似的东西
```

那所有 key 会变成：

```
{aioveu}auth:user:token_version:10
```

但你截图里是 `auth:user:token_version:{10}`，所以 不是 keyPrefix。

---

### 可能 ②（✅ 真正的原因）：Redisson 的 `Map` / `Bucket` 命名约定

你 auth-server 里写 `token_version` 的地方，大概率不是用 `StringRedisTemplate` 写的，而是用了 Redisson 的原生 API：

```java
// 可能是这种写法之一：
RBucket<String> bucket = redissonClient.getBucket("auth:user:token_version:" + userId);
bucket.set("106");

// 或者：
RMap<String, String> map = redissonClient.getMap("auth:user:token_version");
map.put(userId.toString(), "106");
```

Redisson 的 `RMap` 在 Redis 里存的 key 格式是：

```
mapName:{hashKey}
```

所以如果你用了 `RMap`：

```java
RMap<String, String> map = redissonClient.getMap("auth:user:token_version");
map.put("10", "106");
```

Redis 里实际存的 key 就是：

```
auth:user:token_version:{10}     ← 就是这个！
```

---

### 可能 ③：Redisson 的 `getBucket()` 在某些版本里也会加 `{}`

部分 Redisson 版本（特别是 3.17+）在 Bucket 名字里包含 `:` 时，会自动把最后一段用 `{}` 包起来作为 slot hint。

---

## ✅ 修复方案（三选一）

---

### ✅ 方案一（最快）：tenant 读的时候加上 `{}`

```java
String key = "auth:user:token_version:{" + userId + "}";
String value = stringRedisTemplate.opsForValue().get(key);
```

✅ 不改 auth-server
✅ 不动 Redisson 配置
⚠️ 但有点丑，属于"迁就"

---

### ✅ 方案二（✅ 最推荐）：auth-server 改用 `StringRedisTemplate` 写

把 auth-server 里写 `token_version` 的代码统一改成：

```java
@Autowired
private StringRedisTemplate stringRedisTemplate;

stringRedisTemplate.opsForValue().set("auth:user:token_version:" + userId, "106");
```

✅ key 就是纯 `auth:user:token_version:10`
✅ tenant 用 `StringRedisTemplate` 读，完美匹配
✅ 两边都是纯 String，Codec 问题也顺带解决了

---

### ✅ 方案三：两边统一用 Redisson 原生 API

auth-server 写：

```java
RBucket<String> bucket = redissonClient.getBucket("auth:user:token_version:" + userId);
bucket.set(String.valueOf(version));
```

tenant 读：

```java
RBucket<String> bucket = redissonClient.getBucket("auth:user:token_version:" + userId);
String value = bucket.get();  // 注意：这里读出来的 key 可能还是带 {}
```

⚠️ 这个方案下 tenant 还是得确认 key 到底长什么样

---

## ✅ 一句话总结

> `{}` 是 Redisson 自己加的，不是你的问题。
>
> auth-server 用了 Redisson 原生 API（`RMap` 或 `RBucket`）写数据，Redisson 自动给 key 加了 `{}` 包裹。
>
> tenant 用 Spring 的 `StringRedisTemplate` 按纯字符串读，名字对不上，返回 `null`。
>
> 最简单的修法：auth-server 改成用 `StringRedisTemplate` 写，两边统一，干干净净。
