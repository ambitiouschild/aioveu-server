## ✅ 但有一个**非常关键的语义修正**（很重要）

你刚才说的是：

> “登陆时 `tenantResolverProvider` 去获取租户 id”

这句话技术上对，语义上要改一个字：

> ✅ 不是“获取”
>
> ✅ 而是“解析 / 映射”

### ✅ 正确说法（架构级）

> Auth Server 在登录时，根据前端传入的 `clientId`，通过 `PublicTenantResolver` 解析出对应的 `tenantId`，并将其作为认证上下文的一部分。

为什么？
因为：
• `clientId` ≠ 租户

• `tenantId` 是推导出来的

• 推导逻辑必须集中、可控、可审计

### ✅ Auth Server 内部（登录链路）

```java
// 1️⃣ 从 Header 拿 clientId（前端传的）
String clientId = request.getHeader("X-Client-Id");

// 2️⃣ 解析 tenantId（✅ 核心）
Long tenantId = publicTenantResolver.resolve(clientId);

// 3️⃣ 放进上下文（给自己用）
TenantContextHolder.setTenantId(tenantId);

// 4️⃣ Feign 调用 Tenant Service（显式传）
UserAuthCredentials credentials =
    tenantFeignClient.getUserAuthInfoWithTenantId(username, tenantId);

// 5️⃣ 构建 UserDetails
return new SysUserDetails(credentials);

// 6️⃣ JWT 写入 tenant_id
claims.put("tenant_id", tenantId);
```

✅ 每一步都可解释
✅ 每一步都可审计
✅ 没有魔法

## ✅ 为什么要这样设计？（三个不可替代的理由）

### ✅ 1️⃣ 登录阶段 **没有 JWT**

> Token 是登录的结果，不是登录的前提

所以：
• ❌ 不能从 JWT 拿 tenantId

• ✅ 必须从请求上下文推导


---

### ✅ 2️⃣ `clientId` 是“租户的代理凭证”

在很多中台里：

| clientId     | tenantId |
| ------------ | -------- |
| mall-app     | 3        |
| admin-web    | 1        |
| mini-program | 5        |

👉 一对一是最简单的
👉 一对多也可以（但要明确规则）

`PublicTenantResolver` 就是干这个的。

---

### ✅ 3️⃣ `TenantContextHolder.setTenantId()` 在 Auth Server 是“合法的”

注意这个关键区别：

| 服务            | setTenantId 是否合法 |
| --------------- | -------------------- |
| Auth Server     | ✅ 合法（认证阶段）   |
| Resource Server | ❌ 不推荐（只读 JWT） |
| Tenant Service  | ❌ 不推荐（只认参数） |

👉 Auth Server 是唯一允许“产生 tenantId”的地方

## ✅ 一个非常容易被误解的点（重点）

### ❓“那我以后业务请求，还要用 `PublicTenantResolver` 吗？”

### ✅ 答案：**不需要，也不应该**

| 阶段                   | tenantId 来源            |
| ---------------------- | ------------------------ |
| 登录                   | `PublicTenantResolver`   |
| 业务请求               | JWT → `JwtSecurityUtils` |
| Resource Server Filter | JWT                      |

👉 `PublicTenantResolver` 只服务于“无 Token 场景”

## ✅ 你这套设计的“最终定性”

> ✅ 前端传 `clientId`
> ✅ Auth Server 负责 `clientId → tenantId` 的映射
> ✅ 映射结果写入 JWT
> ✅ 下游所有服务只认 JWT
> ✅ `TenantContextHolder` 在 Auth Server 是“权威来源”，在别处是“只读快照”
