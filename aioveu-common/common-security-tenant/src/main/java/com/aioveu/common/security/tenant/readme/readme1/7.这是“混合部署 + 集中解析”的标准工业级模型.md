## ✅ 你描述的模型（我先帮你“抄写”一遍）

> 有公共接口的微服务（PMS / SMS / …）
> - 注入 `common-security-tenant`
> - `PublicTenantFilter` 生效
> - 通过 Feign 调用 `tenant` 服务的解析接口
>
> `tenant` 微服务
> - 同样注入 `common-security-tenant`
> - `PublicTenantFilter` 生效
> - 不走 Feign
> - 直接调用本地 `PublicTenantResolver`（DB / Cache）
>
> 所有服务
> - 下游 SQL / MyBatis 插件只认 `TenantContextHolder`

✅ 100% 正确
✅ 这是“混合部署 + 集中解析”的标准工业级模型
✅ 不是妥协，是正解

## 三、✅ 一个“关键实现点”（你现在这套已经暗示了）

### ✅ `PublicTenantResolver` 的两种实现

```text
TenantFeignResolver   （Feign → tenant 服务）
TenantLocalResolver   （本地 DB / Cache）
```

### ✅ 自动切换逻辑（伪代码）

```java
@Component
@ConditionalOnMissingBean(TenantLoader.class)
public class CommonTenantFeignAutoConfiguration {

    @Bean
    @ConditionalOnProperty(name = "security.tenant.local", havingValue = "true")
    public TenantLoader localTenantLoader(PublicTenantResolver resolver) {
        return resolver::resolve;
    }

    @Bean
    @ConditionalOnBean(TenantFeignClient.class)
    @ConditionalOnMissingBean(TenantLoader.class)
    public TenantLoader feignTenantLoader(TenantFeignClient feignClient) {
        return clientId ->
            feignClient.getTenantIdByClientId(clientId).getData();
    }
}
```

### ✅ tenant 服务配置

```yaml
security:
  tenant:
    enabled: true
    local: true   # ✅ 走本地
```

### ✅ PMS / SMS 配置

```yaml
security:
  tenant:
    enabled: true
    local: false  # ✅ 走 Feign
```

👉 同一套 Filter
👉 同一套 Resolver 接口
👉 两种实现自动切换

## 五、✅ 一个“可以写进 ADR 的结论”

> **平台采用“集中解析、多点入口”的租户解析模型：  
> 所有对外暴露公共接口的微服务通过 Feign 调用 `tenant` 服务完成 `clientId → tenantId` 解析；  
> `tenant` 服务自身通过本地调用完成解析，避免网络回环；  
> 所有服务通过 `TenantContextHolder` 消费租户上下文，解析逻辑全局唯一。**

## 六、❌ 你这套里“唯一需要警惕的点”

### ⚠️ Feign 调用的超时 / 熔断

因为公共接口 强依赖 tenant 服务：

• tenant 服务必须高可用

• Feign 要有 fallback（返回 400，而不是 500）

• 缓存要扛击穿


👉 但这是运维问题，不是架构问题
