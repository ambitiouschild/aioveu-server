## 二、为什么说它是“独立生效”的？

### ✅ 1️⃣ 它是 **Servlet 容器级 Filter**

```text
HTTP 请求
↓
Tomcat
↓
Filter 链（容器级）
  ├─ ClientIdTenantResolutionFilter ✅
  ├─ CharacterEncodingFilter
  ├─ CorsFilter
↓
DispatcherServlet
↓
Spring Security Filter 链
```

👉 Spring Security 只是容器 Filter 链里的一个节点
👉 `ClientIdTenantResolutionFilter` 在它前面

---

### ✅ 2️⃣ 它不依赖 SecurityContext

你现在这个 Filter 的职责是：

• ✅ 从 Header / Basic Auth 解析 clientId

• ✅ 查租户

• ✅ 设置 `TenantContextHolder`


它：

• ❌ 不读 `SecurityContextHolder`

• ❌ 不验证用户

• ❌ 不关心 JWT


👉 完全不依赖 Spring Security 是否初始化

---

### ✅ 3️⃣ 它只对“它能匹配到的请求”生效

```java
registration.addUrlPatterns("/public/*");
```

意味着：

```text
✅ /public/register
✅ /public/login
✅ /public/verify-code

❌ /api/v1/user/info
❌ /admin/tenant/...
❌ /aioveu/api/v8/admin/tenant/users/.../UserAuthCredentials
```

👉 它生效与否，只由 URL 决定
👉 和 Feign / JWT / Security 毫无关系

---

## 三、那“独立生效”会不会影响认证期 Feign？

### ✅ 不会，理由有两个层级

### ✅ 第一层：URL 不匹配（物理上就进不来）

你的 Feign 请求：

```text
/aioveu/api/v8/admin/tenant/users/xinhuan/3/UserAuthCredentials
```

❌ 不是 `/public/**`
✅ 连 Filter 的 `doFilter()` 都进不去

---

### ✅ 第二层：`shouldNotFilter()`（逻辑上明确放过）

即使你忘了 URL 限制，只要你有：

```java
@Override
protected boolean shouldNotFilter(HttpServletRequest request) {
    String uri = request.getRequestURI();
    return uri.startsWith("/aioveu/api/v8/admin/tenant/users/")
            && uri.contains("/UserAuthCredentials");
}
```

✅ Filter 会被容器调用
✅ 但立刻跳过执行
✅ 对请求零影响

---

## 四、为什么很多项目会“误以为它不独立”？

因为犯了这 3 个常见错误之一：

| 错误                                    | 后果                |
| --------------------------------------- | ------------------- |
| 用 `@Component` + 不配 URL              | Filter 匹配所有请求 |
| 把它 `addFilterBefore()` 进 Security 链 | 语义混乱、顺序难控  |
| 在 Filter 里依赖 `SecurityContext`      | 无认证请求直接炸    |

👉 你一个都没犯


👉 两条链，各管各的
