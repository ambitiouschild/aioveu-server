## 二、主流多租户平台的“真实架构”（不是 PPT）

### 1️⃣ 第一层：认证白名单（Security Whitelist）

几乎所有平台都有

```text
/oauth/token
/captcha
/public/**
/actuator/health
```

用途：
• 跳过 JWT 校验

• 给网关、探针、前端、第三方用


叫法各不相同：

| 公司               | 叫法                    |
| ------------------ | ----------------------- |
| Spring Security    | `permitAll`             |
| 阿里               | `authWhiteList`         |
| 腾讯               | `noAuthPaths`           |
| AWS                | `UnauthenticatedRoutes` |
| Kubernetes Ingress | `publicPaths`           |

👉 这是“绝对主流”

---

### 2️⃣ 第二层：租户解析白名单（Tenant Resolution Whitelist）

中大型多租户平台，几乎都有

用途：
• 无 JWT 请求

• 但需要 tenantId

• clientId / apiKey / internal call


典型场景：

• 根据 clientId 查租户

• 根据 openId 查租户

• 根据手机号 / 邮箱查租户

• 平台引导查询（你这个 `/users/tenants/{username}`）


叫法也五花八门：

| 公司       | 叫法                       |
| ---------- | -------------------------- |
| 阿里       | `tenantResolvePaths`       |
| 腾讯       | `bootstrapPaths`           |
| 字节       | `contextInitPaths`         |
| Salesforce | `TenantBootstrapEndpoints` |
| Shopify    | `PlatformProxyPaths`       |

👉 你这个 `TenantResolveProperties.whitelistPaths`，就是标准叫法

## 三、为什么“主流设计”就是两个白名单？

### 因为责任边界是**物理存在**的，不是人为拆的：

```
HTTP 请求
│
▼
【认证层】
│  → 回答：你是谁？要不要登录？
│  → Security Whitelist
│
▼
【租户解析层】
│  → 回答：你以哪个租户执行？
│  → Tenant Whitelist
│
▼
【业务执行层】
│  → MP / ORM
│  → 自动租户隔离
▼
DB
```

👉 这两层之间，永远不可能合并
👉 因为：认证 ≠ 租户
👉 所以：两个白名单是“架构必然”

## 四、那为什么网上“很少看到别人说两个白名单”？

### 原因 1：很多项目**没走到你这一步**

• 单体系统

• 单租户 + 逻辑隔离

• 没有平台表（sys_tenant）

• 没有 clientId 解析


👉 他们根本不需要第二个白名单

---

### 原因 2：很多公司**藏起来了**

• 写在代码里：`if (path.startWith("/internal"))`

• 写在网关：`route.rules`

• 写在 SDK：`@TenantBootstrap`

• 不对外宣传


👉 你看到的“简单方案”，往往是“裁剪后的故事”

---

### 原因 3：很多人**混淆概念**

把：
• 认证白名单

• 租户白名单

• ignore-table

• 参数驱动


全部叫成：
> “多租户配置”

👉 不是他们只有一个
👉 是他们没分清楚

## 五、主流平台“最终形态”是什么？

我给你一个真实工业界的演进路径：

### ✅ Level 1：两个白名单（你现在）

• YAML / 配置

• 清晰、直观

• 适合 1～20 人团队


### ✅ Level 2：白名单 + 注解（你正在走向）

• 新接口用注解

• 老接口 YAML 兜底

• 适合 20～50 人团队


### ✅ Level 3：注解为主，白名单只读（大厂常态）

• 白名单只存遗留接口

• 新语义全靠注解

• 有代码生成 / 扫描工具

• 适合 50+ 人 / 多 BU


👉 没有一个大厂，会“只有一个白名单”
👉 也没有一个大厂，会“全量注解起步”
