## ✅ 一句话先给你（不绕）

> `PublicTenantFilter` 只在两个地方“生效”：`aioveu-gateway` 和 `aioveu-tenant`
>
> ✅ 生效 = 自动装配 + enabled=true + 请求命中白名单
> ❌ 其他地方：根本不该生效

---

## 一、`PublicTenantFilter` 的“生效链条”（非常关键）

### ✅ 完整生效链条（tenant 服务为例）

```text
服务启动
↓
Spring 扫描到 PublicTenantFilter（@Component）
↓
加载 TenantResolveProperties
↓
security.tenant.enabled = true
↓
shouldNotFilter() = false
↓
doFilterInternal() 执行
↓
TenantContextHolder.setTenantId()
```

👉 缺一环，就完全不生效

---

## 二、✅ 用到哪里？（只有这两个）

---

## ✅ 场景一：`aioveu-gateway`（盖章，不解析）

### ✅ 1️⃣ 依赖（必须有）

```xml
<dependency>
    <groupId>com.aioveu</groupId>
    <artifactId>common-security-tenant</artifactId>
</dependency>
```

### ✅ 2️⃣ 配置（必须开）

```yaml
security:
  tenant:
    enabled: true
```

### ✅ 3️⃣ Gateway 过滤器里“让它生效”（核心）

```java
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {

    String clientId = resolveClientId(exchange);

    ServerHttpRequest mutated = exchange.getRequest().mutate()
            .header("X-Client-Id", clientId)
            .header("X-Client-Verified", "true")   // ✅ 关键
            .build();

    return chain.filter(exchange.mutate().request(mutated).build());
}
```

### ✅ 4️⃣ Filter 在 gateway 里“怎么生效”

```text
请求 → Gateway
↓
PublicTenantFilter.shouldNotFilter()
↓
enabled=true + 白名单
↓
doFilterInternal()
↓
verified=true → 走 Gateway 分支
↓
不查 DB / 不查 Feign
↓
直接放行
```

👉 gateway 的 Filter 是“空转”，但必须存在

---

## ✅ 场景二：`aioveu-tenant`（真正解析）

### ✅ 1️⃣ 依赖（必须有）

```xml
<dependency>
    <groupId>com.aioveu</groupId>
    <artifactId>common-security-tenant</artifactId>
</dependency>
```

### ✅ 2️⃣ 配置（必须开）

```yaml
security:
  tenant:
    enabled: true
    whitelist-paths:
      - /public/
      - /openIdAndTenantId/
```

### ✅ 3️⃣ Filter 在 tenant 里“怎么生效”

```text
请求 → tenant 服务
↓
PublicTenantFilter.shouldNotFilter()
↓
enabled=true + URI 在白名单
↓
doFilterInternal()
↓
verified=false → 走 Feign 分支
↓
clientId 从 param 拿
↓
PublicTenantResolver.resolve()
↓
Caffeine Cache
↓
DB / Feign
↓
TenantContextHolder.setTenantId()
```

👉 tenant 服务 = 真正干活

## 三、❌ 为什么 auth / resource 里“不能生效”

### ❌ auth 服务

```yaml
security:
  tenant:
    enabled: false
```

```text
shouldNotFilter() = true
↓
doFilterInternal() 永不执行
↓
Filter 存在，但不生效
```

👉 不是 bug，是设计

---

### ❌ resource 服务

```xml
<!-- 根本不依赖 common-security-tenant -->
```

```text
PublicTenantFilter.class 不存在
↓
连“不生效”的机会都没有
```

👉 物理级不生效

## 四、✅ 怎么确认“真的生效了”？（运维级自检）

### ✅ tenant 服务日志（生效标志）

```text
【PublicTenantFilter】Internal Feign request, clientId:xxx
【PublicTenantFilter】同步解析tenantId: 12
【PublicTenantFilter】设置到上下文 tenantId：12
```

### ✅ gateway 日志（生效标志）

```text
【PublicTenantFilter】Gateway request, clientId:xxx
【PublicTenantFilter】同步解析tenantId: 12
```

### ✅ auth / resource（正确现象）

```text
❌ 没有任何 PublicTenantFilter 日志
```

👉 没日志 = 用对了

## 五、一个“最容易误解”的点（你刚刚跨过去了）

> ❌ “Filter 生效 = 所有服务都执行逻辑”
>
> ✅ “Filter 生效 = 在正确的服务里执行正确的逻辑”

| 服务     | Filter 是否存在 | 是否执行逻辑 |
| -------- | --------------- | ------------ |
| gateway  | ✅               | ✅（盖章）    |
| tenant   | ✅               | ✅（解析）    |
| auth     | ❌ / disabled    | ❌            |
| resource | ❌               | ❌            |
