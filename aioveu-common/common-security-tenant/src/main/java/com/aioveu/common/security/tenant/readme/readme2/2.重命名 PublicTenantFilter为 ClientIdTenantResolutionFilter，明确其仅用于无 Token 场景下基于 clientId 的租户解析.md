## ✅ 一句话定性（先给）

> ❌ `PublicTenantFilter`  
> ❌ “公共租户过滤器”——听起来像是“大家都能用的租户 Filter”

> ✅ 它真正的身份是：
>
> “无 Token 场景下，基于 clientId 解析租户的专用过滤器”

---

## ✅ 为什么现在的名字“不合适”？

### ❌ 问题 1：`Public` 语义模糊

在中台里，“Public”可以是：

• 公共接口 ✅

• 公开数据 ✅

• 公共租户 ❌（你根本没有“公共租户”这个概念）


而你的 Filter 不是给“公共租户”用的，  
它是给 “没有 JWT 的请求” 用的。

---

### ❌ 问题 2：它不是一个“通用租户 Filter”

它：

• ❌ 不解析 JWT

• ❌ 不处理登录态

• ✅ 只认 `clientId`

• ✅ 只服务于无 Token 场景


👉 它和 `TenantFilter`（JWT → ThreadLocal）是“完全不同的物种”

---

### ❌ 问题 3：容易让人误用

以后新人看到：

```java
@Component
public class PublicTenantFilter
```

本能反应会是：

> “哦，这是个通用的租户 Filter，我也能用”

然后：
• 在 Resource Server 里用

• 在有 JWT 的请求里用

• 在 Feign 链路里乱用


👉 你前面那一堆“谁该拿 tenantId”的问题，一半是被这个名字招来的

---

## ✅ 推荐的新名字（按“专业程度”排序）

### ✅ ✅✅ **首选（最推荐）**

```java
ClientIdTenantResolutionFilter
```

理由：
• ✅ 明确说明 输入是 clientId

• ✅ 明确说明 行为是解析（resolution）

• ✅ 不和 JWT / Security 混淆

• ✅ 业界常见命名风格


👉 这是“架构级命名”

---

### ✅ ✅ 次选（也很专业）

```java
AnonymousTenantResolutionFilter
```

理由：
• ✅ “Anonymous” = 无认证

• ✅ 和 Spring Security 的 `AnonymousAuthenticationFilter` 呼应

• ✅ 一看就知道：没登录才用


---

### ✅ 语义型（偏业务）

```java
PreAuthenticationTenantFilter
```

理由：
• ✅ 强调：认证之前

• ✅ 和 OAuth2 术语对齐

## ✅ 改名后的“自我解释型代码”

```java
/**
 * 无认证（无 Token）场景下的租户解析过滤器
 *
 * ✅ 职责：
 * - 从 X-Client-Id / clientId 参数解析 tenantId
 * - 仅用于公共接口、注册、验证码、Feign 内部调用
 *
 * ❌ 不用于：
 * - 已认证请求（JWT 场景）
 * - Resource Server
 *
 * 与 TenantFilter（JWT → ThreadLocal）互斥
 */
@Slf4j
@Component
public class ClientIdTenantResolutionFilter 
        extends OncePerRequestFilter implements Ordered {
```

👉 光看类名 + 注释，新人就不敢乱用

## ✅ 一个非常重要的“架构命名原则”（送你）

> Filter 的名字 = 它的安全边界
>
> - `TenantFilter` → JWT 已认证
> - `ClientIdTenantResolutionFilter` → 无 Token
> - `JwtBlacklistFilter` → 已认证 + 安全增强

名字一旦模糊，安全边界就模糊。

---

## ✅ 你这套 Filter 家族的最终“标准命名”

| Filter                           | 场景                          |
| -------------------------------- | ----------------------------- |
| `ClientIdTenantResolutionFilter` | 无 Token，clientId → tenantId |
| `TenantFilter`                   | JWT → ThreadLocal             |
| `JwtBlacklistFilter`             | JWT 黑名单校验                |
| `ClientIdGatewayFilter`          | Gateway 层 clientId 校验      |

👉 四个 Filter，四种职责，互不重叠
