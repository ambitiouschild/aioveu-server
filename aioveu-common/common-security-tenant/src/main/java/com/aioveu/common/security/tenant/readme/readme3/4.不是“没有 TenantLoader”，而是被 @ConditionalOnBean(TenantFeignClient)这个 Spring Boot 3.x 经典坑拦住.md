你贴的这份 `CommonTenantFeignAutoConfiguration` 非常关键，而且它直接解释了为什么日志里会炸 —— 不是“没有”，而是条件没命中，Bean 没注册进去。我直接把证据钉死，再给你一个“必活”的修复方案。

---

## 一、先给一句话钉死结论

> ✅ 你有 `TenantLoader` 的 Feign 实现代码  
> ❌ 但 `CommonTenantFeignAutoConfiguration` 没生效，所以容器里没有 `TenantLoader` Bean  
> ❌ 于是 `PublicTenantResolver` 走到 `loadTenantId()` 就抛 `IllegalStateException: TenantLoader not configured`

这不是缺类，是 Spring Boot 自动装配条件失败。

---

## 二、从你这个类，逐条对照为什么没生效

你写的条件是：

```java
@ConditionalOnClass(TenantFeignClient.class)     // ①
@ConditionalOnBean(TenantFeignClient.class)      // ②
@ConditionalOnMissingBean(TenantLoader.class)    // ③
@AutoConfigureAfter(FeignAutoConfiguration.class)
```

### ✅ ① `@ConditionalOnClass` —— 大概率过了
`TenantFeignClient` 在 `common-tenant-api` 里，编译期在 classpath → ✅

### ❌ ② `@ConditionalOnBean(TenantFeignClient.class)` —— **这是死穴**

Spring Boot 3.x 下这条规则非常严格：

• `TenantFeignClient` 是 Feign Client Bean

• Feign Client Bean 是由 `FeignClientFactoryBean` 在 后置处理器阶段 注册的

• `@ConditionalOnBean` 在配置类解析早期判断

• 早期：Bean 还没出生 → 条件 false → 配置类直接跳过


👉 这就是你日志里 没有 `TenantLoader` Bean 的根因。

### ✅ ③ `@ConditionalOnMissingBean` —— 本来是对的，但没机会走到

## 四、唯一干净、必活的改法（复制即用）

### ✅ 删掉 `@ConditionalOnBean`，改成“有类就配”

```java
@Slf4j
@Configuration
@ConditionalOnClass(TenantFeignClient.class)        // 类路径有 Feign API
@ConditionalOnMissingBean(TenantLoader.class)       // 没 DB Loader 才上
@AutoConfigureAfter(FeignAutoConfiguration.class)
public class CommonTenantFeignAutoConfiguration {

    @Bean
    @Primary
    public TenantLoader feignTenantLoader(TenantFeignClient tenantFeignClient) {
        return clientId -> {
            log.debug("[FeignTenantLoader] resolve tenantId by clientId={}", clientId);
            return tenantFeignClient.getTenantIdByClientId(clientId).getData();
        };
    }
}
```

✅ 不赌 Bean 早期存在  
✅ 只赌 classpath（稳定）  
✅ 和 DB 版 `TenantLoader` 不冲突
