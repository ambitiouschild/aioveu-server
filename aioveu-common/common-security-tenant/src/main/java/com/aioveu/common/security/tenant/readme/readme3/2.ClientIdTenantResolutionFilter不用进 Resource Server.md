## ✅ 一句话先给结论

> 因为 `ClientIdTenantResolutionFilter` 不属于「资源服务器」的职责边界
>
> ✅ 它是「公共租户解析」
> ✅ 它发生在「认证之前」
> ✅ 它不依赖 JWT、不依赖 OAuth2、不依赖 SecurityContext
>
> 👉 所以它不该进 Resource Server 配置
> 👉 而其他 Filter 必须进，是因为它们“离不开 OAuth2”

## 二、什么叫「资源服务器」？（先把定义钉死）

Resource Server = 被 JWT 保护的服务

它的核心职责只有一句话：

> ✅ 验证 JWT
> ✅ 把 JWT 转成 Authentication
> ✅ 基于 Authentication 做授权

凡是必须依赖 JWT 才能工作的组件  
👉 就必须放进 Resource Server 配置

---

## 三、逐个对比：为什么“其他 Filter 必须加，它不用”

我用一张责任表给你一刀切开 👇

| Filter                           | 是否依赖 JWT           | 是否依赖 SecurityContext | 是否进 Resource Server |
| -------------------------------- | ---------------------- | ------------------------ | ---------------------- |
| `JwtAuthSkippingFilter`          | ❌（但要在 JWT 前执行） | ❌                        | ✅ 必须                 |
| `JwtVersionFilter`               | ✅                      | ✅                        | ✅ 必须                 |
| `JwtBlacklistFilter`             | ✅                      | ✅                        | ✅ 必须                 |
| `TenantFilter`                   | ✅                      | ✅                        | ✅ 必须                 |
| `ClientIdTenantResolutionFilter` | ❌                      | ❌                        | ❌ 不该                 |

## 四、为什么 `ClientIdTenantResolutionFilter` 不用进 Resource Server？

### ✅ 原因 1：它根本不需要 JWT

它的输入是：

```text
Authorization: Basic clientId:secret
或
X-Client-Id
```

👉 不是 Bearer token
👉 不是 JWT
👉 和 OAuth2 Resource Server 半毛钱关系没有

---

### ✅ 原因 2：它处理的请求，本身就“不应该进 Resource Server”

典型路径：

```text
/public/register
/public/login
/public/send-code
```

这些接口：

• ❌ 不需要 JWT

• ❌ 不返回用户资源

• ❌ 不属于 OAuth2 保护范围


👉 它们甚至不应该触发 `BearerTokenAuthenticationFilter`

---

### ✅ 原因 3：它执行得太早了

执行时机是：

```text
HTTP 请求
↓
Tomcat
↓
ClientIdTenantResolutionFilter ✅（容器级）
↓
Spring Security
↓
Resource Server Filter 链
```

👉 Resource Server 还没“醒”
👉 JWT 还没开始解析
👉 Authentication 还不存在

---

### ✅ 原因 4：如果把它加进 Resource Server，反而错

如果你这样写：

```java
http.addFilterBefore(clientIdTenantResolutionFilter, ...)
```

会发生什么？

• 它会被当成“安全组件”

• 新人会以为它依赖 JWT

• 将来有人改顺序，可能把它插到 JWT 后面

• 一旦 JWT Filter 先执行，整个语义就乱了


👉 这不是技术问题，是架构污染

---

## 五、那为什么「其他 Filter」必须进 Resource Server？

### ✅ `JwtAuthSkippingFilter`

• ✅ 目的：在 JWT 认证前决定是否跳过

• ✅ 必须插在 `BearerTokenAuthenticationFilter` 之前

• ✅ 离开 Security 链，它就没有“跳过 JWT”的意义


---

### ✅ `JwtVersionFilter / JwtBlacklistFilter`

• ✅ 输入：JWT

• ✅ 依赖：`JwtAuthenticationToken`

• ✅ 必须发生在 JWT 解码之后、认证完成之前


👉 没有 Resource Server，它们根本拿不到 JWT

---

### ✅ `TenantFilter`

• ✅ 输入：JWT 中的 `tenantId`

• ✅ 依赖：`SecurityContext`

• ✅ 必须发生在 JWT 认证之后


👉 离开 Resource Server，它什么都解析不到

---

## 六、一句话总结它们的“归属逻辑”

> ✅ 谁依赖 JWT，谁进 Resource Server
>
> ✅ 谁在认证前就要决策，谁插在 Security 链前面
>
> ❌ 谁不依赖认证、不依赖 JWT、只做租户解析
> ✅ 谁就留在容器层，独立存在

---

你现在的 Filter 分层是：

```text
【容器层】

```

👉 每一层都在它该在的位置
👉 没有越界，没有错位
