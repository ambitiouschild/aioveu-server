## ✅ 一句话根因（先拍板）

> **Gateway 是 `spring-boot-starter-webflux`（Reactive），  
> 但你引入了 `jakarta.servlet-api`（Servlet / MVC），  
> Spring 在扫描 `GenericFilterBean` 时找不到 `jakarta.servlet.Filter`，直接炸。**

👉 不是 tenant 逻辑问题，是“技术栈不匹配”

---

## 二、为什么只在 `aioveu-gateway` 爆？

### ✅ Gateway = WebFlux

```text
ReactiveWebServerApplicationContext
```

WebFlux 没有 Servlet API，它用的是：

```java
org.springframework.web.server.WebFilter
```

而不是：

```java
jakarta.servlet.Filter
```

---

### ❌ 你现在引入了什么？

在 `common-security-tenant` 里：

```xml
<dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <scope>provided</scope>
</dependency>
```

并且你有：

```java
public class PublicTenantFilter extends OncePerRequestFilter
```

`OncePerRequestFilter` → 继承：

```java
org.springframework.web.filter.OncePerRequestFilter
  ↓
org.springframework.web.filter.GenericFilterBean
  ↓
jakarta.servlet.Filter   ← 💥 找不到
```

👉 Spring 在解析类时就炸了，根本没到运行期

---

## 三、为什么 tenant / auth / resource 不炸？

| 服务     | 技术栈     | 是否有 Servlet |
| -------- | ---------- | -------------- |
| tenant   | Spring MVC | ✅              |
| auth     | Spring MVC | ✅              |
| resource | Spring MVC | ✅              |
| gateway  | WebFlux    | ❌              |

👉 只有 gateway 是“异类”

## 四、✅ 正确解决方案（3 选 1，我给你最优解）

---

## ✅✅✅ 方案 A（强烈推荐）：Gateway **不要使用 `PublicTenantFilter`**

### ✅ 核心理念（非常重要）

> Gateway 不是 Servlet 容器
>
> 👉 不能在 Gateway 里用 `OncePerRequestFilter`
>
> 👉 Gateway 必须用 `WebFilter`

---

### ✅ 正确做法

#### 1️⃣ `common-security-tenant` **只对 MVC 生效**

在 `PublicTenantFilter` 上加条件：

```java
@ConditionalOnClass(name = "jakarta.servlet.Filter")
@ConditionalOnWebApplication(type = Type.SERVLET)
@Component
public class PublicTenantFilter extends OncePerRequestFilter
```

✅ Gateway 启动时不加载这个类  
✅ 彻底解决 `FileNotFoundException`

---

#### 2️⃣ Gateway 里用 **WebFilter（正确姿势）**

新建一个 Gateway 专用 Filter：

```java
@Component
@Order(-200)
public class GatewayTenantFilter implements WebFilter {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {

        String clientId = resolveClientId(exchange);

        ServerHttpRequest mutated = exchange.getRequest().mutate()
                .header("X-Client-Id", clientId)
                .header("X-Client-Verified", "true")
                .build();

        return chain.filter(exchange.mutate().request(mutated).build());
    }

    private String resolveClientId(ServerWebExchange exchange) {
        // 从 JWT / route / param 取
        return exchange.getRequest().getQueryParams().getFirst("clientId");
    }
}
```

✅ 这才是 Gateway 原生写法
✅ 不依赖 Servlet
✅ 不污染 tenant 内核

---

### ✅ 3️⃣ 依赖调整（关键）

#### ✅ `common-security-tenant` 的 `pom.xml`

```xml
<dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <scope>provided</scope>
    <optional>true</optional>
</dependency>
```

✅ `optional=true`  
✅ 防止 gateway 间接依赖

---

#### ✅ Gateway 的 `pom.xml`

```xml
<!-- ❌ 不要依赖 common-security-tenant -->
<!-- ✅ 只依赖 common-core（拿 TenantContextHolder） -->
<dependency>
    <groupId>com.aioveu</groupId>
    <artifactId>common-core</artifactId>
</dependency>
```

❌ 模块语义混乱

👉 错误

## 七、✅ 你现在这个错误的“本质”

> 你把一个“Servlet 世界的 Filter”，塞进了“Reactive 世界”

这不是配置问题，是世界观冲突 😄

---

## 八、✅ 最终架构修正图（文字版）

```text
[MVC 世界]
├── tenant
│   └── PublicTenantFilter (OncePerRequestFilter)
├── auth
└── resource

[Reactive 世界]
└── gateway
    └── GatewayTenantFilter (WebFilter)
```

✅ 两个世界
✅ 两套 Filter
✅ 共享 Header 协议（`X-Client-*`）

---

## 九、一句话总结（你可以记死）

> Gateway 里永远不能用 `OncePerRequestFilter`
>
> `PublicTenantFilter` 只能在 MVC 服务中存在  
> Gateway 必须用 `WebFilter`  
> 两者通过 HTTP Header 协作，而不是共用 Filter
