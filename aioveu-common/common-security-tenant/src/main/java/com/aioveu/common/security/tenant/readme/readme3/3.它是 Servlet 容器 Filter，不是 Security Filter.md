✅ 对，这个 `PUBLIC_TENANT_FILTER = -210` 就是要靠 `order` 值的，而且这是它“唯一正确、也是唯一有效”的方式。

你这个问题问得非常精准，已经把「谁靠 order、谁不靠」的边界摸清楚了 👍  
我直接给你一个钉死级结论 + 为什么它必须靠 order。

---

## ✅ 一句话先给死结论

> ✅ `PUBLIC_TENANT_FILTER` 必须、也只能靠 `order`
>
> ✅ 因为它根本不在 Spring Security 链里
>
> ✅ `addFilterBefore()` 对它完全无效

---

## 二、为什么它「只能」靠 order？

### ✅ 原因 1：它是 **Servlet 容器 Filter**，不是 Security Filter

你这个 Filter 的注册方式是：

```java
@Bean
public FilterRegistrationBean<ClientIdTenantResolutionFilter> publicTenantFilter() {
    FilterRegistrationBean<ClientIdTenantResolutionFilter> bean =
            new FilterRegistrationBean<>(filter);

    bean.setName("clientIdTenantResolutionFilter");
    bean.addUrlPatterns("/public/*");
    bean.setOrder(SecurityFilterOrders.PUBLIC_TENANT_FILTER); // ✅ -210

    return bean;
}
```

👉 这是 Tomcat / Jetty 管理的 Filter 链
👉 不是 Spring Security 的 `SecurityFilterChain`

---

### ✅ 原因 2：`addFilterBefore()` 管不到它

下面这段代码：

```java
http.addFilterBefore(A, B.class);
```

只能管 Security 内部的 Filter

它管不了：

• ❌ `FilterRegistrationBean`

• ❌ `@WebFilter`

• ❌ `ServletContext` 注册的 Filter


👉 Spring Security 根本不知道这个 Filter 的存在

---

### ✅ 原因 3：Servlet 容器 **只认 order**

Tomcat 在启动时：

```text
收集所有 FilterRegistrationBean
↓
按 getOrder() 排序
↓
构建容器 Filter 链
```

✅ order 是唯一排序依据
✅ 没有“相对位置”概念
✅ 没有“插在谁前面”这种说法

---

## 三、那为什么其他 Filter 不靠 order？

因为你把它们放进了 Spring Security 的 Filter 链：

```java
http.addFilterBefore(jwtAuthSkippingFilter,
                     BearerTokenAuthenticationFilter.class);
```

👉 Security 用“相对位置”
👉 order 只是兜底

而 `PUBLIC_TENANT_FILTER`：

• ❌ 不在 Security 链

• ❌ 不参与 `addFilterBefore`

• ✅ 只能靠 order 抢到“最早”


---

## 四、为什么它必须是 `-210`（甚至更早）？

因为你的目标是：

```text
HTTP 请求
↓
ClientIdTenantResolutionFilter ✅（最早）
↓
Spring Security Filter 链
↓
JWT / 认证 / 授权
```

如果它 order 不够小：

```java
int PUBLIC_TENANT_FILTER = 10;
```

那执行顺序可能变成：

```text
CharacterEncodingFilter
CorsFilter
Spring Security Filter 链
ClientIdTenantResolutionFilter ❌（太晚）
```

👉 租户上下文来不及设置
👉 MyBatis / 数据权限全错

---

## 五、你这个 order 值，**是不是“最优值”？**

### ✅ 是，而且是非常专业的写法

```java
int PUBLIC_TENANT_FILTER = -210;
```

为什么好？

| 优点         | 说明                         |
| ------------ | ---------------------------- |
| ✅ 足够早     | 早于几乎所有容器 Filter      |
| ✅ 有预留空间 | 前面还能插 `-300`, `-250`    |
| ✅ 语义清晰   | 一看就是“租户解析最早”       |
| ✅ 不冲突     | 不跟 Security 内置 Filter 抢 |

👉 这是“架构级常量”，不是随便拍脑袋的数字
