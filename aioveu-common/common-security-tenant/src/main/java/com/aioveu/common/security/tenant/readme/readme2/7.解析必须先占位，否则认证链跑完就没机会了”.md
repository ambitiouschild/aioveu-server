## ✅ 一句话先给（关键认知）

> 这里的 `-210` 不是“解析替代认证”
>
> ✅ 而是：在“认证链还没决定结果之前”，先把 tenantId 准备好
>
> ✅ 真正的认证判断，仍然发生在 Security 的 Filter Chain 里
>
> ✅ order 靠前 ≠ 认证被跳过

👉 你看到的不是“解析 > 认证”
👉 你看到的是“解析为认证做准备”

## 二、为什么 order 小，反而是“对”的？

### Spring Filter 的黄金法则：

> order 越小 → 越早进入 Filter Chain
>
> 但不代表 → 越早“做决定”

### 你的两个 Filter 的真实角色：

| Filter                                 | Order | 角色                        |
| -------------------------------------- | ----- | --------------------------- |
| `PUBLIC_TENANT_FILTER`                 | -210  | 准备上下文                  |
| `SecurityContextPersistenceFilter`     | ~-110 | 恢复 / 创建 SecurityContext |
| `UsernamePasswordAuthenticationFilter` | ~-50  | 执行认证                    |
| `AnonymousAuthenticationFilter`        | 0     | 兜底匿名身份                |

👉 -210 只是“先进场”
👉 认证 Filter 才是“做判决”

## 四、为什么必须“解析在前”？（这是核心）

### 因为你的场景是：

> 无 JWT + 需要 tenantId

如果顺序反过来：

```text
Security 先执行
↓
发现：无 JWT
↓
创建 AnonymousAuthentication
↓
进入 Controller
↓
MP 需要 tenantId
↓
TenantContextHolder = null
↓
SQL 失败
```

👉 逻辑直接崩

所以必须：

> ✅ 在 Security 建立 AnonymousAuthentication 之前
> ✅ 先把 tenantId 放进 ThreadLocal
> ✅ 让 MP 有值可用

## 五、那这不就和“先认证后解析”矛盾了吗？

### 不矛盾，因为你混淆了两个概念：

| 概念                          | 含义                     |
| ----------------------------- | ------------------------ |
| 认证（Authentication）        | 决定：你是谁、有没有身份 |
| 租户解析（Tenant Resolution） | 决定：以哪个租户执行     |

### 正确的顺序是：

```
1️⃣ 认证链开始
2️⃣ 租户解析（为匿名请求准备上下文）
3️⃣ 认证链结束（确立身份）
4️⃣ 业务执行（使用上下文）
```

👉 解析嵌在认证链内部，而不是在认证链之前
👉 解析是“认证过程中的一个准备步骤”

---

## 六、一句话把“顺序悖论”解开

> ❌ 错误理解：
> “order 小 = 先认证 / 后解析”

> ✅ 正确理解：
> “order 小 = 先进入 Filter 链”
>
> ✅ 认证是“过程”
> ✅ 解析是“过程中的一个环节”
>
> ✅ 解析必须发生在：Security 确立身份之前

---

## 七、为什么我之前说“先认证后解析”也没错？

因为那是从“决策语义”角度说的：

> “认证先表态：能不能进”
> “解析后表态：怎么执行”

而从Filter order 角度：

> “解析必须先占位，否则认证链跑完就没机会了”

👉 两个说法都对
👉 只是视角不同

---

## 八、给你一个“不会再看错”的判断公式

> 问自己：
>
> “这个 Filter 是在‘做决策’，还是在‘准备数据’？”

| Filter             | 角色     |
| ------------------ | -------- |
| JWT 校验           | 决策     |
| 权限判断           | 决策     |
| ClientId 解析      | 准备数据 |
| TenantContext 设置 | 准备数据 |
| 上下文清理         | 善后     |

✅ 准备数据的 Filter，order 必须更小
✅ 做决策的 Filter，order 相对靠后
