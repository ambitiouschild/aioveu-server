## 二、为什么你这个顺序是“对的”

### 1️⃣ `PUBLIC_TENANT_FILTER = -200`

Spring Security 关键过滤器顺序（简化版）：

| Filter                                 | 大约 order |
| -------------------------------------- | ---------- |
| `ChannelProcessingFilter`              | -200       |
| `WebAsyncManagerIntegrationFilter`     | -100       |
| `SecurityContextPersistenceFilter`     | -110       |
| `UsernamePasswordAuthenticationFilter` | -50        |
| `AnonymousAuthenticationFilter`        | 0          |
| `FilterSecurityInterceptor`            | 100        |

你的 `-200`：

✅ 早于 Security 认证链  
✅ 早于 `SecurityContextPersistenceFilter`  
✅ 早于 MyBatis / MP  
✅ 不抢 Spring Security 的“主流程”

👉 这是“黄金位置”

## 三、唯一一个“工程级微调建议”（非必须，但强烈推荐）

### ⚠️ 问题点（很小，但真实存在）

你现在：

```java
int PUBLIC_TENANT_FILTER = -200;
```

但 Spring 内部过滤器未来可能微调顺序，  
而且第三方 starter 也可能插队。

### ✅ 更稳的写法：**留安全缓冲位**

```java
int PUBLIC_TENANT_FILTER = -210;
```

或者更明确一点：

```java
/**
 * 公共租户解析过滤器
 * 早于 SecurityContextPersistenceFilter(-110)
 * 早于 MyBatis / MP
 */
int PUBLIC_TENANT_FILTER = -210;
```

✅ 原因：
• `-200` 太“整数友好”，容易被人类选

• `-210` 明确表示“我比你早，但不贴脸”

• 给未来留 10 个 slot，防止“插队战争”
