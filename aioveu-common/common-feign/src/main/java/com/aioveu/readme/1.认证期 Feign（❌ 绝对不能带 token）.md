## 二、Feign 调用分三种身份，你得分清

### ✅ 第一类：用户态 Feign（✅ 可以 / 应该带 token）

场景：
• 用户已登录

• Controller 里有 `SecurityContext`

• 下游是业务资源服务


例子：
```text
订单服务
→ 用户请求
→ Feign → 用户服务（需要当前用户身份）
```

✅ 这时 Feign 应该带 JWT
✅ 通常用：
```java
OAuth2FeignRequestInterceptor
```

👉 这是“用户发起的请求，Feign 代为转发”

---

### ✅ 第二类：系统态 Feign（✅ 可以带 client_credentials）

场景：
• 没有用户

• 服务 ↔ 服务

• 调用的是系统级接口


例子：
```text
调度服务
→ Feign → 通知服务
```

✅ 这时 Feign 应该带 `client_credentials` token
✅ 代表“我是谁的系统”

👉 这是“系统身份”，不是“用户身份”

---

### ❌ 第三类：认证期 Feign（❌ 绝对不能带 token）

场景：
• OAuth2 Password 模式

• 正在认证

• JWT 还没发出来


例子（你这个）：
```text
/oauth/token
→ SysUserDetailsService
→ Feign → tenant 服务
```

❌ 不可能有 JWT
❌ 不应该有 JWT
❌ 带 JWT 是逻辑错误

👉 这是“认证基础设施内部调用”
👉 不是资源访问
👉 不是用户请求

---

## 三、为什么你这个 Feign **不能**带 token（不是“不建议”）

### 1️⃣ 时间线上不可能

```text
POST /oauth/token
↓
认证还没完成
↓
JWT 还没签发
↓
Feign 调用 tenant 服务
```

👉 JWT 是认证的结果，不是前提

---

### 2️⃣ 如果带了 token，会发生什么？

假设你强行给它一个 token：

• ❌ 要么是旧的

• ❌ 要么是别的用户的

• ❌ 要么是client_credentials


👉 TenantFilter 会误判身份
👉 日志、审计、租户全部错乱

---

### 3️⃣ 你之前给自己定的红线，已经排除了这种可能

你反复强调：

> ❌ TenantFilter 只认 JWT
> ❌ 不信任前端 tenantId
> ❌ 不兜底

👉 那这个请求：
• ❌ 不是 JWT 场景

• ❌ 不是用户场景


👉 它就不该走 JWT 通道

## 四、所以 Feign 到底“能不能带 token”？

我给你一个工程级判断表：

| Feign 场景      | 是否带 token | 用什么 token       |
| --------------- | ------------ | ------------------ |
| 用户请求转发    | ✅ 必须       | 用户 JWT           |
| 系统任务 / 定时 | ✅ 应该       | client_credentials |
| 内部工具调用    | ✅ 可以       | client_credentials |
| 认证期调用      | ❌ 禁止       | ❌ 不存在           |
| 健康检查        | ❌ 不建议     | ❌                  |
| 注册 / 验证码   | ❌ 禁止       | ❌                  |

👉 你这个，正好落在最后一行
