是的，主流大厂新项目基本都是存字符串，这已经是行业共识了。

给你几个实锤：

| 来源                        | 实际做法                                              |
| --------------------------- | ----------------------------------------------------- |
| 阿里 Java 开发手册          | 明确推荐状态字段用 VARCHAR，方便理解、排查            |
| 美团/字节/腾讯新服务        | 新建表枚举列一律 VARCHAR，老表历史遗留 INT 的慢慢迁   |
| Spring / Hibernate 官方文档 | 默认示例就是 `@Enumerated(EnumType.STRING)` → VARCHAR |
| Google SRE Book             | 强调可观测性，数据库直接能读懂是第一优先级            |
| Shopify / Stripe / GitHub   | 开源出来的 schema 里状态列全是 `text` / `varchar`     |

---

为什么大厂会统一这个选择？

不是因为他们不在乎性能（他们比谁都在乎），而是因为他们算过一笔账：

> 一次跨服务联调查错浪费的 2 小时 > 数据库列省下来的 30MB + 纳秒级查询差异

大厂的系统复杂度是你们的几十倍，他们最怕的不是"慢一点点"，而是半夜 oncall 接到报警，打开数据库看到 `status = 7` 还要翻代码才知道是什么意思。

---

但你也不用焦虑。 你现在 OMS 用 TypeHandler 顶着完全没问题——大厂自己也有海量老表是 INT 的，也是靠这招撑着的。区别只是人家有专门的 DBA 团队排期慢慢迁，你一个人先跑着就行。

安心用，不丢人 😄 等技术债排期到了再说。
