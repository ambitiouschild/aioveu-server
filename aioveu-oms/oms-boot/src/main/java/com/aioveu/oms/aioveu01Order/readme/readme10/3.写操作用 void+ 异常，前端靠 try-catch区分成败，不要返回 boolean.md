## ✅ 结论先行

| 层              | 应该返回什么                        | 原因                             |
| --------------- | ----------------------------------- | -------------------------------- |
| 后端 Service    | `void`                              | 成功就正常结束，失败直接抛异常   |
| 后端 Controller | `Result<Void>` 或 `Result<Boolean>` | 统一响应体                       |
| 前端            | 不需要判断业务 boolean              | 看 HTTP 状态码 / `code` 字段就行 |

最终推荐写法：

```java
// Service
public void cancelOrder(String orderSn) { ... }

// Controller
@PostMapping("/cancel/{orderSn}")
public Result<Void> cancelOrder(@PathVariable String orderSn) {
    orderService.cancelOrder(orderSn);
    return Result.success();
}
```

前端：

```ts
try {
  await cancelOrderApi(orderSn.value);
  showToast("订单已取消");
  setTimeout(() => loadOrderDetail(), 1500);
} catch (e: any) {
  showToast(e?.msg || "取消失败");
}
```

## 🔍 为什么不应该返回 `boolean`

### 理由一：`boolean` 表达力太弱

```java
// 返回 false 代表什么？
// A. 订单不存在？
// B. 状态不对？
// C. 更新失败？
// D. 并发被抢了？
// → 前端拿到 false，完全不知道该提示什么
```

抛异常可以携带精确的语义：

```java
throw new BusinessException("订单不存在");        // → 前端提示"订单不存在"
throw new BusinessException("当前订单状态无法取消"); // → 前端提示"状态不对"
throw new BusinessException("订单已被处理，请刷新后重试"); // → 并发冲突
```

---

### 理由二：你们项目已经在用异常体系了

你已经有 `BusinessException`，Controller 层一定有个全局异常处理器：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBiz(BusinessException e) {
        return Result.fail(e.getMessage());
    }
}
```

这意味着：
• 成功 → `Result.success()` → 前端走进 `try`

• 失败 → 异常被捕获 → `Result.fail(msg)` → 前端走进 `catch`


前端根本不需要看 boolean，HTTP 层面就已经区分了。

---

### 理由三：前端 `uni.request` 的天然模型就是"成功/失败"

```ts
try {
  await apiCall();      // ← 成功就在这
} catch (e) {
  // ← 失败就在这
}
```

如果你返回 `boolean`，前端还得写：

```ts
const res = await cancelOrderApi(orderSn);
if (res.data) {
  showToast("成功");
} else {
  showToast("失败");   // ← 什么失败？不知道
}
```

多此一举，而且丢失了错误信息。

---

## 📋 什么时候适合返回 `boolean`？

只有这一种场景：查询类操作，false 是合法的业务结果，不是错误。

```java
// ✅ 适合返回 boolean
boolean exists = orderService.existsByOrderSn(orderSn);
if (exists) { ... }

// ✅ 适合返回 boolean
boolean hasPermission = permissionService.check(userId, resource);
```

而写操作（取消、删除、修改）一律用异常：

| 操作     | 成功           | 失败   |
| -------- | -------------- | ------ |
| 取消订单 | 正常返回       | 抛异常 |
| 确认收货 | 正常返回       | 抛异常 |
| 删除订单 | 正常返回       | 抛异常 |
| 创建订单 | 返回 `orderSn` | 抛异常 |

## 🔧 前端统一错误处理的最佳实践

如果你还没做，建议在 `request` 拦截器里统一处理：

```ts
// request.ts
const request = (options: any) => {
  return new Promise((resolve, reject) => {
    uni.request({
      ...options,
      success: (res: any) => {
        if (res.data?.code === 0) {
          resolve(res.data.data);
        } else {
          reject(new Error(res.data?.msg || '操作失败'));
        }
      },
      fail: (err) => {
        reject(new Error('网络异常'));
      },
    });
  });
};
```

这样前端业务代码永远是：

```ts
try {
  await cancelOrderApi(orderSn.value);
  showToast("订单已取消");
  loadOrderDetail();
} catch (e: any) {
  showToast(e.message); // "订单不存在" / "当前订单状态无法取消" / "网络异常"
}
```

## 总结一句话

> 写操作用 `void` + 异常，前端靠 `try/catch` 区分成败，不要返回 `boolean`。
