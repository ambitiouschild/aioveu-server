你这个 `uploadShipping(String orderSn)` 是系统自动发货（定时任务 / 支付回调 / 消息驱动），没有前端 `ShipOrderDTO` 传入。那 `logistics_type`、trackingNo、expressCompany 全部只能从 DB 里已有的数据来。

这完全合理，而且你的代码已经走了一半了——`delivery` 已经查出来了。缺的只是把这些数据桥接到微信请求体里。

## 你的现状分析

```java
OmsOrderDelivery delivery = omsOrderDeliveryService.selectByOrderId(order.getId());
// delivery 里有：deliveryCompany、deliverySn、receiverPhone...
```

问题：你的 `delivery` 字段名跟我之前假设的不太一样：

| 你的字段                        | 含义                         |
| ------------------------------- | ---------------------------- |
| `delivery.getDeliveryCompany()` | 快递公司名称（如"顺丰速运"） |
| `delivery.getDeliverySn()`      | 物流单号                     |
| `delivery.getDeliveryStatus()`  | 同步状态                     |

但微信要的是 `express_company_code`（如 `"SF"`），不是公司名称。而且你没有 `logisticsType` 的来源。

## 解决方案：自动发货走自己的分支

不要让自动发货复用"手动发货的 dto 路径"，它们数据来源不同，硬凑在一起只会越来越乱。

### 方案：在 `OrderServiceImpl` 里写一个**自动发货专用方法**

```java
/**
 * 自动发货（定时任务 / 支付回调 / MQ 消费 调用）
 * 所有参数从 DB 读取，不需要前端 DTO
 */
@Transactional(rollbackFor = Exception.class)
public JsonNode autoUploadShipping(String orderSn) {

    log.info("【自动发货】开始，orderSn={}", orderSn);

    OmsOrder order = getByOrderNo(orderSn);
    if (order == null) {
        throw new RuntimeException("订单不存在");
    }

    // 校验订单状态
    if (order.getStatus() != OrderStatusEnum.PAID.getValue()) {
        log.warn("【自动发货】订单未支付，跳过 orderSn={}", orderSn);
        return buildSkippedResult();
    }

    OmsOrderDelivery delivery = omsOrderDeliveryService.selectByOrderId(order.getId());
    if (delivery == null) {
        throw new RuntimeException("发货信息不存在");
    }

    // 已同步过就跳过
    if (delivery.getDeliveryStatus() == OrderDeliveryStatusEnum.SYNCED) {
        log.info("【自动发货】微信已同步，跳过 orderSn={}", orderSn);
        return buildSkippedResult();
    }

    // 判定物流类型
    LogisticsTypeEnum logisticsType = determineLogisticsTypeForAuto(order, delivery);

    // 校验物流信息完整性
    if (logisticsType.needTrackingNo()) {
        if (StrUtil.hasBlank(delivery.getDeliverySn())) {
            throw new RuntimeException("物流单号不完整，无法自动发货 orderSn=" + orderSn);
        }
        if (StrUtil.hasBlank(delivery.getDeliveryCompanyCode())) {
            throw new RuntimeException("快递公司编码不完整，无法自动发货 orderSn=" + orderSn);
        }
    }

    // 获取 openid
    String openid = getOpenidByMemberId(order.getMemberId());

    // 构建 item_desc
    List<OmsOrderItem> items = orderItemService.list(
            Wrappers.<OmsOrderItem>lambdaQuery().eq(OmsOrderItem::getOrderId, order.getId())
    );
    List<WeChatApiClient.ItemDesc> itemDescs = items.stream()
            .map(i -> new WeChatApiClient.ItemDesc(
                    i.getSpuName() + "【" + i.getSkuName() + "】",
                    i.getQuantity()
            ))
            .collect(Collectors.toList());

    // 构建 shipping_items
    List<WeChatApiClient.ShippingItem> shippingItems = new ArrayList<>();
    if (logisticsType == LogisticsTypeEnum.PHYSICAL) {
        shippingItems.add(new WeChatApiClient.ShippingItem(
                delivery.getDeliverySn(),
                delivery.getDeliveryCompanyCode(), // ← 必须是微信编码
                maskPhone(delivery.getReceiverPhone())
        ));
    }

    // 组装请求体
    ObjectNode requestBody = weChatApiClient.buildShippingRequestBody(
            order.getOutTradeNo(),
            logisticsType.getValue(),
            shippingItems,
            itemDescs,
            openid
    );

    log.info("【自动发货】请求体组装完成，orderSn={}, logisticsType={}",
            orderSn, logisticsType.getValue());

    // 调微信
    JsonNode response = weChatApiClient.uploadShippingInfo(order.getClientId(), requestBody);
    log.info("【自动发货】微信返回成功: {}", response);

    // 更新同步状态
    delivery.setDeliveryStatus(OrderDeliveryStatusEnum.SYNCED);
    delivery.setUpdateTime(LocalDateTime.now());
    omsOrderDeliveryService.updateById(delivery);

    // 更新订单状态
    order.setStatus(OrderStatusEnum.SHIPPED.getValue());
    order.setLogisticsType(logisticsType.getValue());
    this.updateById(order);

    log.info("【自动发货】完成，orderSn={}", orderSn);
    return response;
}
```

## 自动发货专用的判定方法

```java
/**
 * 自动发货时判定物流类型（没有前端 DTO，全靠 DB）
 */
private LogisticsTypeEnum determineLogisticsTypeForAuto(OmsOrder order, OmsOrderDelivery delivery) {

    // 1. 优先用订单上存的
    if (order.getLogisticsType() != null) {
        LogisticsTypeEnum fromOrder = LogisticsTypeEnum.fromValue(order.getLogisticsType());
        if (fromOrder != null) return fromOrder;
    }

    // 2. 看 delivery 里有没有单号
    if (StrUtil.isNotBlank(delivery.getDeliverySn())) {
        return LogisticsTypeEnum.PHYSICAL;
    }

    // 3. 兜底：虚拟商品（无物流）
    return LogisticsTypeEnum.VIRTUAL;
}
```

## 你现在缺的一个字段：快递公司编码

你 `delivery` 里有 `deliveryCompany`（名称），但微信要的是 编码。

### 两种解法（选一个）：

解法 A：delivery 表加一个 `delivery_company_code` 字段（推荐）

```sql
ALTER TABLE oms_order_delivery
ADD COLUMN delivery_company_code VARCHAR(32) COMMENT '快递公司微信编码，如 SF/ZTO/YTO';
```

下单或 ERP 推送物流信息时同时写入编码。

解法 B：用 Map 做名称→编码的转换（过渡方案）

```java
private static final Map<String, String> COMPANY_NAME_TO_CODE = Map.of(
        "顺丰速运", "SF",
        "顺丰", "SF",
        "中通快递", "ZTO",
        "中通", "ZTO",
        "圆通速递", "YTO",
        "圆通", "YTO",
        "韵达快递", "YD",
        "韵达", "YD",
        "申通快递", "STO",
        "申通", "STO",
        "京东物流", "JD",
        "EMS", "EMS",
        "极兔速递", "JTSD",
        "德邦快递", "DBLK"
);

private String resolveExpressCode(String companyName) {
    if (companyName == null) return null;
    // 精确匹配
    String code = COMPANY_NAME_TO_CODE.get(companyName);
    if (code != null) return code;
    // 模糊匹配
    for (Map.Entry<String, String> entry : COMPANY_NAME_TO_CODE.entrySet()) {
        if (companyName.contains(entry.getKey())) {
            return entry.getValue();
        }
    }
    log.warn("【自动发货】未知的快递公司名称: {}", companyName);
    return null;
}
```

然后自动发货时：

```java
String expressCode = StrUtil.isNotBlank(delivery.getDeliveryCompanyCode())
        ? delivery.getDeliveryCompanyCode()
        : resolveExpressCode(delivery.getDeliveryCompany());

if (logisticsType == LogisticsTypeEnum.PHYSICAL && StrUtil.isBlank(expressCode)) {
    throw new RuntimeException("无法确定快递公司编码，company=" + delivery.getDeliveryCompany());
}
```

## 最终架构总结

```
┌──────────────────────────────────────────────────────────┐
│                    两条发货路径                           │
├──────────────────────────┬───────────────────────────────┤
│     手动发货（运营）       │      自动发货（系统）         │
│  Controller → uploadShip  │  Job/MQ → autoUploadShipping │
│  参数来源：ShipOrderDTO    │  参数来源：DB（order+delivery）│
│  前端传 logisticsType     │  order.logisticsType 读取     │
│  前端传 trackingNo        │  delivery.deliverySn 读取     │
│  前端传 expressCompany    │  delivery.deliveryCompanyCode │
│  微信成功后回写 delivery   │  微信成功后更新 sync_status   │
└──────────────────────────┴───────────────────────────────┘
```

两条路各自独立，不互相干扰，也不用强行共用一个方法签名。
