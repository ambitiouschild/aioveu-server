啊对，你说得对，我搞混了——你现在操作的是 OMS 服务，OMS 的 `oms_order` 表里 `payment_channel` 和 `payment_method` 存的是 INT（code），这个没问题。

但你 OMS 服务里没有直接连 `pay_order` 表，那是 PAY 服务的库。所以第二步那个 `INNER JOIN pay_order` 的 SQL 你在 OMS 这边跑不了，得去 PAY 服务的数据库跑，或者换个思路。

---

## 重新给你一个 OMS 视角的清理方案

### 第一步：OMS 本地先看看 NULL 的分布

```sql
-- 在 OMS 的 oms_order 表上跑
SELECT 
    status,
    COUNT(*) as cnt
FROM oms_order
WHERE payment_method IS NULL OR payment_channel IS NULL
GROUP BY status;
```

### 第二步：OMS 自己能做的——直接按枚举对齐补齐

既然你 OMS 这边没有 `pay_order` 表可 JOIN，那就根据你已知的业务事实来补：

你这个项目目前只有微信支付 + JSAPI 对吧？ 如果是的话，所有 NULL 直接补成：

```sql
-- 在 OMS 数据库跑
UPDATE oms_order
SET 
    payment_channel = 2,   -- WECHAT
    payment_method = 3     -- JSAPI
WHERE payment_method IS NULL 
   OR payment_channel IS NULL;
```

> ⚠️ 唯一的风险：如果有少量订单是余额支付（BALANCE, channel=4, method=7），会被误标成微信。但看你 260 条的数据量，你可以先跑完再抽查几条 `status>=2` 的订单去微信商户后台对一下，基本不会错。

---

### 第三步：如果不确定有没有非微信订单，先隔离再补

更稳妥的做法：

```sql
-- 1. 先把已支付的 NULL 订单导出来人工确认
SELECT id, order_sn, status, total_amount, create_time
FROM oms_order
WHERE status >= 2
  AND (payment_method IS NULL OR payment_channel IS NULL);

-- 2. 确认完再批量更新（假设你确认全是微信 JSAPI）
UPDATE oms_order
SET payment_channel = 2, payment_method = 3
WHERE status >= 2
  AND (payment_method IS NULL OR payment_channel IS NULL);

-- 3. 未支付的也补上（反正下次支付成功会回写覆盖）
UPDATE oms_order
SET payment_channel = 2, payment_method = 3
WHERE status = 1
  AND (payment_method IS NULL OR payment_channel IS NULL);
```

---

### 第四步：根本解决——支付回调里回写

这是 OMS 这边你能控制的、最重要的防线。你现在的 `PaymentSuccessConsumer` 消费到消息后，处理完业务一定要把渠道和方法写回去：

```java
// 在你的 handlePaymentSuccess 方法里，更新订单状态时加上这两列
LambdaUpdateWrapper<OmsOrder> wrapper = new LambdaUpdateWrapper<OmsOrder>()
    .eq(OmsOrder::getOrderSn, msg.getOrderNo())
    .set(OmsOrder::getStatus, OrderStatusEnum.PAID.getValue())
    .set(OmsOrder::getPaymentChannel, mapChannel(msg.getChannel()))  // ← 加
    .set(OmsOrder::getPaymentMethod, mapMethod(msg))                  // ← 加
    .set(OmsOrder::getPaymentTime, msg.getPaymentTime());

this.update(wrapper);

private PaymentChannelEnum mapChannel(String channel) {
    return PaymentChannelEnum.fromValue(channel) != null 
        ? PaymentChannelEnum.fromValue(channel) 
        : PaymentChannelEnum.WECHAT; // 兜底
}

private PaymentMethodEnum mapMethod(PaymentSuccessMessage msg) {
    // 如果消息里带了 method 字段就用，没有就兜底 JSAPI
    if (msg.getMethod() != null) {
        return PaymentMethodEnum.fromValue(msg.getMethod());
    }
    return PaymentMethodEnum.JSAPI;
}
```

这样以后每笔新订单支付成功都会自动补齐，不会再产生 NULL。

## 总结（OMS 视角，可执行）

| 步骤 | 在哪跑   | 做什么                                                       |
| ---- | -------- | ------------------------------------------------------------ |
| ①    | OMS DB   | `GROUP BY status` 看 NULL 分布                               |
| ②    | OMS DB   | `UPDATE SET channel=2, method=3 WHERE NULL`（微信 JSAPI 兜底） |
| ③    | OMS 代码 | `PaymentChannelEnum.fromCode` 加 null 兜底                   |
| ④    | OMS 代码 | `PaymentSuccessConsumer` 回写 channel + method               |

这样 OMS 这边数据就彻底干净了，不会再 500。你先跑①看看分布，确认一下是不是基本全是微信 JSAPI，我就帮你把 UPDATE 语句定死 👊
